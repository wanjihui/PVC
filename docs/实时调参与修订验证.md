# 2026-10-09 实时调参与修订验证

本轮修订基于 DeepSeek 历史会话审查。改前文件备份在 `_live_tuning_before_20261009`。未刷写WiFi模块内部固件，修改的是RT1064侧源码；未下载到车上，未提交或推送Git。

## 控制与数据分析修正

- 去除自动弯道降速，默认直弯同速150cm/s；K1才发车，K2直接清PWM。500ms线性起步、全程速度反馈和陀螺阻尼继续启用。
- 保留视觉KP1=1.6、KP2=0.012、KD=0.3、上限240deg/s；陀螺阻尼恢复0.08，四轮PI恢复Kp=0.10、Ki=0.001、Kd=0、ff=0，以便先比较视觉修改效果。
- 删除反复poll的忙循环；每次网络推进至多启动一次DMA，主循环末尾当前延时1ms。
- 固定前瞻55行的默认值移入config.h；参数实体和23项校验统一由control_params.c管理。
- 数据分析采用MCU samples计时，排除尾部停车样本，分别看起步与后续。yaw差分仍来自同一IMU，不能作为独立转向达成率；不再凭平均绝对误差断言所有轮子持续欠速。人工拦车片段仍需排除。

## 在线读写

上位机“06实时调参”管理巡航速度、斜坡时间、固定前瞻、死区、视觉P/二次P/D、转向上限、陀螺阻尼、横移增益、四轮独立Kp/Ki/Kd及正误差附加ff。

```text
电脑 -> 模块6666: MCAR GET 101 ALL\n
电脑 -> 模块6666: MCAR SET 102 omega_kp1 1.8\n
模块 -> 电脑8082: [PARAM] 102 OK omega_kp1 1.79999995
模块 -> 电脑8082: [PARAM] 103 ERR STOP_FIRST
```

以上`\n`表示实际换行字节。GET返回23项及DONE标志，回复保留float精度。固件按换行拼接SPI分片，限制长度和工作量，拒绝未知项、非有限数、越界及非法整数。ramp_ms须停车修改并为5ms整数倍。其他值运行中可改，速度环输出累计值和误差历史保留；下一次视觉帧或5ms中断使用新值。K1重新起步清PID但保留本次在线增益。

cruise_cms=0只去掉前进速度，不能代替K2停车。该协议没有发车指令，也不写Flash。断电恢复config.h；上位机保存/导入方案不会自动发给车。

上位机校验回复来源IP及请求编号，未确认前不更改实际值。超时显示未确认并可重试：超时并不证明固件没有应用，要重新读取。UDP可丢包，模块切换发送端口时的命令接收仍需要实车确认。

命令接收采用与TX共享DMA/mutex的异步只读SPI；每次接收结束重新计时，使慢主循环不会连续接收而饿死发送。PARAM回复只进入WiFi日志缓存，避免一次读取23项造成同步串口打印阻塞。

## 你接下来执行

1. 用Keil编译下载McarPVC；上电仍保持停止。
2. 运行WiFiSPI_Monitor的`release_20261009_live_tuning_001`新版，01页确认模块IP和命令端口6666并开始三路监听。
3. 进入06页读取参数，确认收到车辆的23项实际值。先停车修改一项、确认回复，再测试运行中小步修改；斜坡时间需按K2后调整。
4. 按K1上赛道，仍以150cm/s直弯同速；同时看边界图、vis_err_px、omega_cmd_dps、四轮target/speed/duty。按K2停止，保存参数方案和本轮数据。
5. 第一轮先用默认参数比较。调参时一次修改一个值，修改范围只表示固件允许范围，并不代表全范围适合这辆车。

完整控制链、实际函数和参数调大调小的依据见[控制原理与实时调参说明](控制原理与实时调参说明.md)。
