# 手动编码器与IMU验证（历史版本）

2026-10-07。用于核对四路编码器的实车位置和方向，并记录IMU航向角速度。

当前已恢复`main -> app_poll`和独立速度闭环，手动测试入口已移除；K1会驱动电机。以下为旧手动验证版本的归档，不代表当前固件行为。当前操作见[四轮独立速度环调试](四轮独立速度环调试.md)。

用户手动确认原FL/FR字段对应反了，已在config.h交换前轮完整硬件通道与方向补偿。当前FL使用QTIMER1_ENCODER2（A=C2、B=C24，反向修正1），FR使用QTIMER1_ENCODER1（A=C0、B=C1，反向修正0）。RL/RR、电机引脚和上位机协议保持原配置。旧CSV中的enc_FL实际是右前，enc_FR实际是左前，解读旧记录时需先交换两列。

## 当前行为

`MOTOR_DUTY_TEST_ENABLE=1`保持当前验证入口；虽然沿用历史开关和`app_motor_test_poll()`名称，本次已经移除四轮10%输出。主循环注释`app_poll()`，四次`motor_set_wheel()`的占空比均固定为0。上电、K1、K2和重连期间都不会主动驱动电机，不执行速度PID或视觉转向。

上电先配置电机PWM=0和编码器，然后静止校准ICM20602。IMU就绪后才启动5ms采样；若IMU失败，日志记录失败阶段，编码器仍可使用，IMU字段为NaN。参数包协议未修改。

K1只打开WiFi发送许可，K2关闭许可；同时按下时K2优先。暂停发送期间编码器和已就绪IMU仍持续采样，累计计数不会清零。WiFi保持连接，启动日志在K1后补发；K2事件保存在串口和缓存，下次K1后补发。

## 操作步骤

1. 编译下载后复位，整车放稳，等待IMU静止校准和WiFi入网完成。不要刚上电就转轮或转动车身。
2. 上位机选择“综合验证（IMU＋编码器）”，参数端口8081、日志8082，开始监听，再按K1。日志应出现`MCAR_MANUAL_ENCODER_IMU`、`IMU OK`及`PWM ALWAYS 0`。
3. 手动向前转动左前轮，只有`enc_FL`应明显递增；再依次转动右前、左后、右后，分别核对`enc_FR`、`enc_RL`、`enc_RR`。每次转一轮，其他轮保持静止，各次之间停顿约2秒。反向转动时，该字段应递减。开头累计值不一定为0，判断变化量和方向，不判断累计值的正负。
4. 告诉我每个实车轮子实际使哪个字段变化。若不对应，请记录完整四轮对应关系，不要先自行修改方向补偿。
5. 确认编码器位置后，整车放平，手动将车头向左转，再向右转，观察`gz_dps`（上位机预设中Z轴角速度gyro_z的实际字段名）。按当前x向前、y向左、z向上的安装约定，左转应为正、右转应为负，单位deg/s；静止时应接近0。只转轮、车身不转时，gz_dps接近0是正常现象。
6. 保存全部解析数据CSV，按K2结束发送。之后再恢复有电机输出的直行采集，对照轮速与IMU；本次不能靠K1进行落地自动直行。

## 字段与周期

沿用60字节小端`<9f4i2I>`，无需更新上位机程序：

| 字段 | 偏移 | 单位/含义 |
|---|---|---|
| roll / pitch / yaw | 0 / 4 / 8 | deg |
| gx_dps / gy_dps / gz_dps | 12 / 16 / 20 | deg/s；固定静止校准后角速度 |
| ax_g / ay_g / az_g | 24 / 28 / 32 | g |
| enc_FL / enc_FR / enc_RL / enc_RR | 36 / 40 / 44 / 48 | 修正方向后的累计整数count |
| samples | 52 | 编码器5ms采样次数 |
| seq | 56 | 发送序号 |

PIT_CH0每5ms采编码器和就绪IMU，PIT_CH1每10ms识别按键。K1后参数目标每50ms发送（20Hz），日志每1000ms调度。摄像头本次不初始化，也没有图像发送。

编码器继续使用已验证的一倍频，119.02906 count/cm；转换轮速时使用`Δenc / 119.02906 / (Δsamples × 0.005)`。重新K1后跨越暂停间隔的首组差分不作为连续运行速度。
