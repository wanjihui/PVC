# 四轮独立速度环调试

2026-10-07历史阶段记录：以下描述APP_VISION_TRACKING_ENABLE=0时的独立轮速测试。当前默认已恢复视觉（开关=1），沿用这里的PI参数；当前操作见[视觉循迹实跑采集](视觉循迹实跑采集.md)。

## 当前流程

main只调用一次app_init，再在while中持续调用app_poll，不再直接下发固定PWM。app_poll依次处理按键动作、可选视觉、停车重连、WiFi。独立轮速测试配置`APP_VISION_TRACKING_ENABLE=0`，流程中循迹调用注释，不初始化相机、不处理图像、不触发视觉停车。恢复为1后沿用同一流程接回视觉外环。

PIT_CH0每5ms先更新编码器，再更新就绪IMU，最后执行Speed_PID_Crtl。四轮使用本轮编码器速度和本轮PI状态计算占空比。速度环是电机运行输出的唯一来源；上电初始化和K2停车也可以清PWM。

上电PWM=0，先静止校准ICM20602。K1清四轮PID历史状态，将四个Target都设为150cm/s，然后开启速度环。K2连续按下约20ms由扫描中断直接关闭速度环、清目标/输出/PWM，并停止周期参数/图像传输；必要日志继续独立提交。K1/K2同时出现时只执行K2，不短暂启动。再次K1重新清历史状态启动，无固定40%起步、无速度切换阈值、无起步超时或速度爬升阶段。

IMU失败时不给发车许可，日志保留失败阶段；WiFi失败不阻止固定采样和控制，重连只在停车期间进行。日志同步输出UART并进入WiFi缓存。WiFi连通后立即提交启动日志，不需按K1；启停和异常日志无论停车/运行都每1000ms最多尝试提交一次，发完后空缓存不产生UDP包。初始化时上位机应提前开始监听；UDP不保证接收端晚启动仍能补收已提交日志。本次没有周期寄存器刷屏。

## 初调参数

ENCODER_CLOSED_LOOP_ENABLE=1，四輪初始Kp=0.10、Ki=0.0010、Kd=0、Kff=0。Ki是每5ms一步的离散系数，公式不额外乘周期。第一拍在实际速度0、目标150时内部输出约15.15%，转换为整数PWM后下发15%。之后输出由反馈计算，不是固定15%启动。

这组参数尚未经过实车闭环验证，应根据目标、实际、输出曲线再分别调整。输出保持现有±100%物理范围，目标速度单位cm/s。四轮占空比不要求相同。编码器保持一倍频与119.02906 count/cm；FL=C2/C24、FR=C0/C1、RL=C3/C4、RR=C5/C25，反向修正1/0/1/0。

## 上位机与记录

新版解析规则增加“四轮速度环”。参数端口8081，日志8082；仍用原网络配置。参数目标每50ms上传一次（20Hz）。同一108字节小端包保留原来的60字节IMU/累计编码器前缀，再追加12个float32：

| 字段 | 偏移 | 单位 |
|---|---|---|
| target_FL / FR / RL / RR | 60 / 64 / 68 / 72 | cm/s，四轮目标 |
| speed_FL / FR / RL / RR | 76 / 80 / 84 / 88 | cm/s，最近一次5ms内环实际轮速 |
| duty_FL / FR / RL / RR | 92 / 96 / 100 / 104 | %，本拍实际提交的整数占空比，逻辑前进为正 |

gz_dps仍位于20，单位deg/s。samples@52、seq@56不变。旧综合验证规则仍能解析前60字节，但不会显示新增的调参字段。

PID目标/实际/PWM快照在短临界区整批复制；网络发送在临界区之外。IMU/编码器快照分别复制，因此不能认为包内所有传感器完全同一时刻。speed字段是5ms瞬时区间速度，累计enc差计算的是两次收包间的平均速度，两者短时不同是正常的。电脑接收时间不用于控制定时。

烧录后保持整车静止完成校准。上位机选择“四轮速度环”，开始监听，按K1短距离落地测试，按K2停止，保存全部解析数据CSV。勾选同一轮target/speed/duty比较响应，并保留gz_dps观察车身转向。0.2–0.5秒窗口平均用于评估稳定速度，不改变5ms内环周期。
