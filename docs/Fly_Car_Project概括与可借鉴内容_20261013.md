# Fly_Car-Project：内容概括与采用建议

参考 https://github.com/Nanqi-mo/Fly_Car-Project ，已下载到 `references/Fly_Car-Project`，main提交 `901aeaa292f28a12b831f37fe53d98b3d7de599e`。阅读README、全部3个公开C文件及2份Word说明；原仓库未修改。它是半开源飞行汽车，公开内容不构成可直接编译的完整工程。

## 仓库实际包含什么

- `Control.c`：四旋翼位置/角度/角速度控制调用、地面舵机控制、GPS航点导航、陆空切换状态机。
- `isc.c`：1ms PIT处理、核间遥控快照读取、控制更新标志。
- `RC.c`：遥控串口FIFO、iBUS式帧解析、校验、通道有效性、离线保护、手动/自动模式路由。
- 两个立创EDA `.epro` 工程：`P3+KG`、`DRV8701`驱动板；未在本轮打开EDA做电气设计验证。
- 两份Word项目/设计说明、结构与展示图片。

README介绍平台为SR6P3C4三核：Core0控制、Core1遥控、Core2 GPS。地面是舵机阿克曼转向加左右驱动电机，空中是四旋翼，IMU为IMU660RA，目标是遥控/GPS航点陆空导航。它没有公开麦轮运动学、视觉循迹、十字补线或WiFiSPI异步驱动；不能把本仓库当作这几项的直接替代实现。

## 最值得借鉴：外环给目标，内环跟踪角速度

`Control_Plane()` 先用 `PID_YAW_Angle` 计算航向角误差的输出，再执行：

```c
PID_Attitude_Cal(&PID_YAW_Rate,
                 PID_YAW_Angle.OutPut,
                 (float)GYRO_Real_z);
```

它明确把角度环输出作为角速度环目标，角速度环结果再进入四电机推力混控。我们的车目前是视觉生成omega，再减gyro×0.30后直接做麦轮逆解，没有独立的角速度误差PID。

可借鉴结构：视觉给期望车体角速度，IMU内环跟踪这个目标，产生轮速差修正，再交给四轮速度环。视觉仍负责贴线，不必先做绝对yaw锁定；六轴IMU的yaw漂移也不适合不加约束地长期锁航向。此思路有助于处理出弯仍转、转向反向后迟迟未执行，但不能保证消除麦轮侧滑。PID系数、输出单位、采样率、混控符号都必须重新设计，本轮未采用。

## 可借鉴但应按需使用

|内容|源码做法|对McarPVC的意义|建议|
|---|---|---|---|
|角度跨±180处理|`control_wrap_angle_deg()`把角差约束到±180|以后航向保持/定角转弯避免359°与1°被认为差358°|需要角度外环时再用；目前角速度不用包角|
|状态转换锁存/滞回|到点0.5m锁存，离开1.2m再解锁；陆空切换互锁|弯道减速/恢复可用不同进入退出门槛及持续稳定条件，避免反复加减速|借鉴原则，不照搬距离和计数|
|退出时清控制状态|停车/异常/模式切换时清输出并调用PID_Init|避免重新发车沿用旧积分或差分误差|先核对本车已有实现；本车发停重置已有，勿重复|
|通信帧完整校验|帧头、32字节长度、校验和、6通道800～2200范围|新网络类型协议也应按类型/长度明确区分、无效包不更新控制数据|本轮MUDP已借鉴这种校验原则，无需换它的遥控协议|
|中断只收、后续解析|UART回调把字节存FIFO，轮询状态机解析完整帧|避免中断内执行复杂文本解析、保留跨包状态|现有异步WiFi/FIFO思路已经类似|
|独立任务分频|1ms设置Rate/Turn、5ms Angle、10ms Position标志|快慢控制环分工值得参考|RT1064现有5ms/约20ms足够做首轮角速度反馈，不因三核项目改成1kHz|

## 公开实现的限制与不能照搬的点

1. `Control_Car()`虽然定义了左右电机PID对象，公开函数却直接把 `Car_control.Car_Speed` 赋给左右PWM，转向靠舵机；没有这里能核实的独立轮速PID调用。它不是比我们四轮闭环更完整的地面速度方案。
2. `PID_Attitude_Cal/PID_Position_Cal/PID_Init`的定义、PID参数、主要头文件和main没有公开，无法确认积分限幅、D项滤波、抗饱和、总调度开销或编译行为。文档里的能力说明不能替代缺失源码。
3. `isc.c`中的1ms/5ms是置标志周期，缺少main，不能保证每个标志都按该频率实际被消费；10ms与20ms还都设置Position同一个标志。不能直接以此判断本车需要更高频率。
4. 遥控离线阈值为调用计数50，公开部分无法核实 `RC_Online_Check()` 调用周期；不能称为确定50ms超时。也不要把用于人工遥控的断线停机照搬成WiFi调试窗口关闭即停车——本车WiFi是旁路调试链路。
5. 自动飞行pitch计算出现 `Target_Angle.pitch + Target_Angle.pitch`，切换计数50的注释写200次；存在需结合完整工程确认的疑点，不能盲信注释或复制整段。
6. 本车角度为度、控制yaw左转正；它地面调用使用 `-IMU_Data.yaw/10`，其底层单位没有公开，不能复制该符号/比例。

## 对本轮甩尾问题的判断

本仓库最有价值的是角速度串级反馈的结构，以及状态转换滞回；并没有现成的麦轮弯道减速算法或视觉边界补线。建议先采用低成本的弯道降速对照，再决定是否引入独立车身角速度反馈。通信固定单socket修订可单独验证，不与这些控制改动混在同一轮。

以上供用户选择，本轮没有迁移其控制算法、参数或硬件配置。
