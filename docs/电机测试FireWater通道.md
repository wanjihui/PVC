# 电机测试 FireWater 通道

适用于 `MOTOR_TEST_ENABLE=1` 的独立电机验证入口。

## 串口与格式

- UART1：TX=B12，RX=B13；115200、8N1。
- VOFA+ 数据协议选择 **FireWater**。
- 每帧固定 20 个十进制整数，用英文逗号分隔，以 `\r\n` 结束。
- 运行采样约每秒一帧；四轮输出仍每次主循环更新，硬件 PWM 持续输出。
- 启动、引脚配置、初始化提示保留为完整换行的文本日志，显示在文本接收区，不混入数字采样行。库断言失败时仍保留原有错误日志。
- 程序只读取寄存器，没有检测驱动电源、电机接线或实际转速。

官方协议说明：[VOFA+ FireWater](https://www.vofa.plus/docs/learning/dataengines/firewater/)。它支持逗号分隔的采样数字帧，以及独立的文本日志帧。

## 通道表

VOFA+ 通道从 **CH0** 开始编号。

| 通道 | 内容 | 单位 / 含义 |
|---|---|---|
| CH0 | 主循环累计次数 | 正常持续增加，采样间隔约增加100 |
| CH1 | 测试指令占空比 | %，来自 `MOTOR_TEST_DUTY`，当前为20 |
| CH2 | M1 DIR输出寄存器 | 0或1；不是外部引脚电压测量 |
| CH3 | M2 DIR输出寄存器 | 0或1；不是外部引脚电压测量 |
| CH4 | M3 DIR输出寄存器 | 0或1；不是外部引脚电压测量 |
| CH5 | M4 DIR输出寄存器 | 0或1；不是外部引脚电压测量 |
| CH6 | PWM2运行掩码 | 十进制；四个子模块运行时预计为15（0xF） |
| CH7 | PWM2 OUTEN寄存器 | 十进制；当前引脚配置预计为960（0x03C0） |
| CH8 | M1 PWM比较值 | PWM2 SM1 VAL3 |
| CH9 | M1 PWM周期值 | PWM2 SM1 VAL1+1 |
| CH10 | M2 PWM比较值 | PWM2 SM0 VAL3 |
| CH11 | M2 PWM周期值 | PWM2 SM0 VAL1+1 |
| CH12 | M3 PWM比较值 | PWM2 SM3 VAL5 |
| CH13 | M3 PWM周期值 | PWM2 SM3 VAL1+1 |
| CH14 | M4 PWM比较值 | PWM2 SM2 VAL5 |
| CH15 | M4 PWM周期值 | PWM2 SM2 VAL1+1 |
| CH16 | 配置的PWM频率 | Hz，当前17000 |
| CH17 | 配置的串口波特率 | 当前115200 |
| CH18 | 电机测试开关 | 当前1 |
| CH19 | 运行阶段 | 3表示已进入电机测试主循环 |

四路占空比可分别用 `CH8/CH9`、`CH10/CH11`、`CH12/CH13`、`CH14/CH15` 判断；20%时应约为0.20。这些比值与运行掩码反映寄存器配置，实际信号仍需在主板和驱动输入端测量。

CH1 是指令百分比，不是速度测量；当前未使用编码器。

## DIR读数修正

旧诊断版使用 `gpio_get_level()` 读取 GPIO 的 PSR 输入状态。逐飞库 `gpio_iomuxc()` 将 SION 设为0，在GPIO输出模式下未强制开启输入回读，因此不能用旧版 CH2~5 的全0结果判断物理方向脚为低电平。

修正版使用 `GPIO_PinRead()` 读取与 `gpio_set_level()` 相同端口的 DR 输出寄存器。当前正20%指令且四路方向补偿均为0，预计 CH2~5 为 `1,1,1,1`。此结果证明软件输出寄存器被置高，实际引脚与驱动输入端电压仍需万用表或示波器测量。本次修正只改变诊断读取，不改变电机输出或引脚配置。

## 恢复循迹模式后

`MOTOR_TEST_ENABLE=0` 时，原有 `control_vofa_send()` 仍使用 FireWater 20 通道，通道含义恢复为四轮速度、目标、输出、视觉及控制状态等，不能沿用本表。该模式的发送间隔由 `VOFA_SEND_DIV` 控制。
