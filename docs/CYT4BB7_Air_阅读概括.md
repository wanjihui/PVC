## 这个仓库是什么

它是第 21 届智能汽车竞赛“飞跃雷区”项目的空中控制端。飞机需要估计自己的姿态、高度和运动状态，控制飞行，并处理相机信息、与地面车通信。因此，除了 IMU，这里还有飞控、图像、规划和通信代码。

主工程使用 CYT4BB7 双核 Cortex-M7，工程入口在 `project/iar`；McarPVC 使用 RT1064 和 Keil。仓库还附带独立的 STM32F411 固件目录。PCB、完整空地系统背景和硬件迭代在作者母仓库维护，不包含在本次下载的 Air 子仓库中。

| 目录 | 主要内容 | 对你有什么用 |
|---|---|---|
| `project/user` | 双核启动、主循环和中断；Core 0 运行估计与控制，Core 1 处理相机和图像数据 | 理解固定周期任务、高低频任务的分工 |
| `project/code/Estimation/Attitude` | IMU 采集、校准、滤波、Mahony 姿态解算 | 最值得优先阅读 |
| `project/code/Estimation/Height_Est` | IMU 与多路 TOF 的高度估计、倾斜补偿和异常测距处理 | 学习多传感器融合和坏数据剔除 |

## IMU 模块怎么工作

主链路可以理解为：

```text
ICM42688 三轴陀螺仪 + 三轴加速度计
    ↓
陀螺仪去零偏、加速度计校准
    ↓
角速度陷波/低通、加速度低通
    ↓
Mahony：融合角速度和重力方向，更新四元数
    ↓
roll / pitch / yaw 和滤波角速度
    ↓
飞控反馈，以及高度/速度估计所需的姿态信息
```

| 文件 | 重点看什么 |
|---|---|
| `IMU_TOP.c` | 从 `IMU_Init_All()`、`IMU_Update_1000HZ()` 看整体调用顺序，包括自检、暖机、校准、滤波和解算 |
| `IMU_Filtter.c/.h` | 滤波器如何初始化、更新；采样频率与截止频率如何关联 |
| `Accel_Calibration.c/.h` | 六面/椭球校准、偏置和比例/轴间误差修正、传感器到机体坐标转换、参数保存 |
| `MahonyAhrs.c/.h` | 四元数更新、加速度可信度、静止判定、零偏学习、归一化和异常恢复 |

当前 IAR 主工程使用 `MahonyAhrs`；目录中的 `Mahony_temp.c` 是另一份实现，不是优先学习入口。

**角速度与角度的区别：**陀螺仪直接告诉你“现在转得多快”，例如 30°/s；姿态解算告诉你“当前朝向或倾斜角度是多少”。你的麦轮车转向反馈首先需要可靠的 Z 轴角速度；之后要做指定角度转弯、保持朝向，才需要进一步使用航向角。

Mahony 中的加速度计用来提供重力方向，帮助修正 roll 和 pitch。运动产生的加速度会干扰这件事，所以这里会降低不可信加速度的权重。六轴 IMU 没有绝对航向观测，yaw 仍会漂移。作者文档中的低漂移效果是其飞机上的实测描述，不等于换一块板子也有相同性能。

## 适合你的学习顺序

1. **先学单位、坐标和标定。**分清原始 LSB、°/s、rad/s 和 g；确认正方向；静止时检查零偏。它的静止判定结合角速度和加速度，你当前项目主要根据车辆运行状态控制零偏跟踪，可以参考这种测量判据。
2. **学如何看数据。**作者同时观察原始和处理后的数据，并结合频谱判断振动来自哪里。你的串口 VOFA 已有基础，之后可以记录原始/滤波 gyro_z、零偏、转向目标和控制输出；真正分析频率时，需要足够的记录采样率，当前约 25 Hz 的显示数据不能用于观察高频振动。
3. **再学滤波。**滤波越强，反馈延迟也可能越大。作者更换机架后重新分析振动频带，说明参数必须跟着实际硬件与采样率重新选择。
4. **需要姿态时再读 Mahony。**先理解陀螺仪积分、加速度修正和四元数归一化，再看自适应权重、静止零偏学习等增强逻辑。算法本身比芯片驱动容易复用，但仍需适配单位、坐标和周期。
5. **学串级控制与 PID 的工程细节。**`FlightController/pid_core.c` 包含明确的 dt、积分限幅、可选抗积分饱和、测量值微分和 D 项滤波。抗积分饱和默认关闭，阅读时应结合调用处看实际配置。

对于你的麦轮车，后续可考虑的结构是：

```text
视觉误差 → 目标车体角速度
                     ↓
             与 gyro_z 比较 → 角速度反馈控制
                     ↓
       vx、vy、旋转控制量 → 麦轮运动学分配
                     ↓
               四个车轮速度环 → PWM
```

做指定航向时，可以在目标角速度之前增加“航向角误差 → 角速度目标”的外环。具体实现仍要统一单位与输出含义，并调好各环的频率和增益。你的当前代码主要使用 gyro_z 作转向阻尼；编码器尚未接入，四轮目前是临时开环输出，以上结构是未来改进思路。

## 迁移到 McarPVC 时需要重新适配

| 项目 | 下载仓库 | 你的 McarPVC |
|---|---|---|
| 主控 / 主工程 | CYT4BB7 / IAR | RT1064 / Keil |
| 当前 IMU | ICM42688 | ICM20602 |
| IMU 更新周期 | 1 ms，1000 Hz | 5 ms，200 Hz |
| 正航向 / 正 Z 轴角速度 | 俯视顺时针 | 俯视逆时针，即左转 |
| 运动执行器 | 四旋翼的桨叶推力混控 | 麦轮四个轮子的速度分配 |

源码中的默认滤波参数是 300 Hz 陷波、80 Hz 陀螺仪低通、25 Hz 加速度低通。你的 200 Hz 采样的奈奎斯特频率是 100 Hz，不能直接使用这里的 300 Hz 陷波参数，也不能继续使用 1 ms 的积分周期。需要按车上的实际采样率和振动数据重新设计。

还应留意实现与注释是否一致：当前 `IMU_Init_All()` 自检失败后只是打印提示，之后仍继续初始化并将 `g_imu_ready` 置为 1，不能把它当成可靠的故障阻断机制。静止零偏学习和角速度死区也要在真实慢转场景中验证，避免把有效的小角速度当作偏置或噪声。

建议的阅读入口：`docs/01-flight-control/imu-and-attitude.md` → `IMU_TOP.c` → `IMU_Filtter.c` → `MahonyAhrs.c` → `Accel_Calibration.c` → `FlightController/pid_core.c`。六面校准和更复杂的椭球拟合可以分阶段学习，不必第一遍就读完大文件。
