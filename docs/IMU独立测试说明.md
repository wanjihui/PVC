# ICM20602 独立测试说明

**当前入口更新：** 已按用户下一步要求切换编码器独立测试，`IMU_TEST_ENABLE=0`、`ENCODER_TEST_ENABLE=1`。本说明保留IMU模式操作；重新运行IMU时需设`IMU_TEST_ENABLE=1`，并关闭其余三个测试开关。

更新日期：2026-10-04。用户已确认实际传感器为 ICM20602。

代码编译与电脑姿态内核验证通过，不代表传感器硬件已经通过。需要下载到核心板后按以下步骤测试。

## 当前程序

- `IMU_TEST_ENABLE=1`，`MOTOR_TEST_ENABLE=0`，`WIFI_SPI_TEST_ENABLE=0`。
- 初始化四路电机PWM为0，并调用`motor_stop()`；PIT不执行轮速PID，按键不发车。
- 不启动摄像头、编码器、循迹、按键扫描或旧TCP/图像业务。
- ICM20602：SPI4，SCK=C23、MOSI=C22、MISO=C21、CS=C20；WiFi模块使用独立的SPI1。
- WiFi名称/密码保持当前配置；目标电脑`192.168.50.117:8081`，模块本地UDP端口6666。
- 先连接WiFi，再读取芯片ID、核对寄存器，静止采集300次，计算三轴陀螺仪固定零偏。
- PIT_CH0每5ms读取六轴数据、计算姿态；主循环每轮延时50ms，再发送UDP和打印串口。
- 50ms之外还存在SPI、打印耗时，因此上传不是严格20Hz；IMU采样独立于主循环上传。

## 下载与上位机

1. Keil打开`project/mdk/rt1064.uvprojx`，目标`nor_sdram_zf_dtcm`，编译、下载当前程序。
2. 上位机`WiFiSPI_UDP_IMU_Model(1).exe`沿用监听`0.0.0.0:8081`。
3. 二进制解析保持：roll=float32/偏移0/小端，pitch=float32/偏移4/小端，yaw=float32/偏移8/小端。
4. 从上电到出现`IMU calibration DONE`前保持板子静止，建议一直放稳，等收到真实角度后再拿起。
5. 启动标识应为`MCAR_IMU_WIFI_UDP_TEST`。若仍为`MCAR_WIFI_SPI_UDP_TEST`，运行的是旧通信测试程序。
6. 串口若已连接，UART1 B12=TX、B13=RX，115200，VOFA协议FireWater。DAP本身不保证提供UART通道。

UDP负载仍严格12字节，只含真实姿态角；串口日志、六轴值、发送序号和采样计数没有加入UDP。上位机不需要改协议。当前未增加无线文字日志功能。

## 分步验证

| 操作 | 观察 | 判定与限制 |
|---|---|---|
| 静止放稳约10秒 | 三轴角速度接近0，roll/pitch稳定；加速度模长接近1g | 静止角速度建议先观察是否约在±1deg/s内；这是初步筛查标准，不是芯片合格指标 |
| 绕传感器X轴缓慢转动，停在约30度 | gx有正负变化，roll对应变化；停住后gx回到近0 | roll是角度，gx是角速度；停住后角度保留，角速度回零 |
| 绕传感器Y轴缓慢转动 | gy与pitch变化 | 方向与传感器轴定义相对应，先不要套用车头左右 |
| 板子近水平，绕Z轴旋转约90度 | gz变化，yaw累计约90度 | 若传感器+Z朝上，俯视逆时针为正；+Z朝下则相反 |
| 在新姿态停住，再返回原姿态 | roll/pitch回到原值，yaw大致返回 | 六轴没有绝对航向参考，yaw会漂移；用短时间往返验证 |
| 六面静止放置（可后续做） | 每个轴分别约+1g/-1g，另两轴近0 | 确认轴方向、比例与安装；本程序只校陀螺仪零偏，不校加速度六面误差 |

不要只用3D模型的视觉方向判定接线或轴符号。当前角度遵循传感器XYZ轴，尚未测定传感器与车体的安装映射；需先看数值，再对应实物动作。正常循迹用的`IMU_MOUNT_YAW_SIGN`保持原值，本测试姿态没有单独反转gz，避免破坏三轴坐标一致性。

roll通常在-180~180度，pitch在-90~90度，yaw在-180~180度附近换算。yaw穿越边界时会从约180跳到-180，是角度表示方式；pitch接近±90度时欧拉角存在奇异性，roll/yaw可能明显变化。初步测试避免该姿态，内部四元数仍保持归一化。

## 串口FireWater通道

启动阶段输出说明文字；运行阶段每行固定16项数字加CRLF。通道编号从1开始。

| 通道 | 内容 | 单位/含义 |
|---|---|---|
| 1、2、3 | roll、pitch、yaw | deg，与UDP同一采样快照 |
| 4、5、6 | gx、gy、gz | deg/s，已减三轴上电零偏 |
| 7、8、9 | ax、ay、az | g，1g约9.8m/s² |
| 10 | samples | 实际执行的IMU更新次数，约每秒增加200 |
| 11 | tx_seq | 上传尝试序号；只在UART，当前UDP没有此字段 |
| 12 | send_status | 0模块发送流程成功，1数据未全部交给模块，2立即UDP提交失败 |
| 13 | unsent_bytes | 未交给模块的字节数，正常0 |
| 14 | late_samples | 两次采样入口间隔大于7.5ms的次数；理想0 |
| 15 | max_update_us | PIT内采集+解算的最大耗时，应明显低于5000us |
| 16 | interval_us | 最新两次PIT采样入口间隔，约5000us |

加速度模长计算：`sqrt(ax*ax + ay*ay + az*az)`。平放时只有与重力方向接近的轴约±1g，三轴不应全为0。

`send_status=0`只表示模块应答成功，不保证上位机没有遗漏。上位机CSV时间戳由电脑添加，不是IMU采样时间。

## 初始化异常

`IMU test STOPPED stage=`后的编号：

- 1：芯片初始化失败，先看供电和SPI4接线；库初始化会核对WHO_AM_I=0x12。
- 2：校准期间平均加速度模长不在0.75~1.25g内，检查数据、供电、接线和是否在运动。
- 3：某轴陀螺仪校准波动超过3deg/s，放稳后复位；这里只能粗略筛查运动，匀速旋转未必被检出。
- 4：芯片ID、采样分频或滤波寄存器读回不符，检查SPI通信。

出现错误时不启动IMU PIT，也不会发车；修正后复位重试。WiFi初始化失败时当前联合测试同样停止，保留串口错误阶段信息。

## 参数与解算限制

- 传感器量程沿用库默认±8g、±2000deg/s；分别按4096LSB/g、16.4LSB/(deg/s)转换。
- 库默认SMPLRT_DIV=7，在当前滤波模式下是125Hz；独立测试运行时改为4，即200Hz，并核对读回。不修改逐飞库源文件，正常循迹路径没有同步改变。
- 陀螺仪CONFIG=3，约41Hz低通；加速度沿用约44.8Hz低通。
- 六轴姿态采用三轴去零偏陀螺仪积分+重力方向比例纠偏，四元数归一化；输出Euler角给上位机。
- `IMU_TEST_FUSION_KP=2.0`为初始增益，需根据手动倾斜的响应、恢复速度和噪声实测调整。
- 仅加速度模长0.8~1.2g时使用重力纠偏；这只能屏蔽明显的加速干扰，不能消除所有运动加速度影响。
- yaw没有磁力计或其他外部航向参考，会累积零偏误差；本模式用于基础硬件与方向验证，不是已经标定好的导航姿态系统。
- DWT周期计数测量实际更新间隔与执行耗时；正常抖动使用实际dt积分。超过10倍目标周期时不尝试用陈旧角速度恢复丢失期间的转动，计数与间隔会提示异常。
