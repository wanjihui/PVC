## 已做的临时调整

- `WIFI_SPI_ENABLE=0`：WiFi业务模块不参与编译，不初始化、不连接、不上传；源码保留。
- `ENCODER_ENABLE=0`：不初始化或读取四路编码器，轮速PID暂时旁路。
- `printf`沿用逐飞库自带重定向，发送至UART1。没有重复修改库的`fputc`。
- KEY_1不再先用40%PWM冲到180cm/s，而是直接进入限幅开环运行。
- KEY_2和视觉停车事件立即关闭PWM；没有反馈时无法按实测速度反向制动或确认停稳。
- 堵转检测暂时关闭。零轮速占位不能证明车辆静止或被卡住。
- 每次发车清零斑马线上升沿和连续出界计数。
- 修正VOFA第20通道浮点格式，以及图像误差至麦轮转向的符号映射。

## 如何连接VOFA

用USB-TTL模块，或ARM下载器提供且已连接的虚拟串口。
USB线只接在下载器上，并不代表其串口信号已接到核心板。

| RT1064 | USB-TTL |
|---|---|
| B12（UART1 TX） | RX |
| GND | GND |
| B13（UART1 RX，可选，目前只观察输出） | TX |

信号电平使用3.3V TTL，开发板保持正常供电。
VOFA设置：选择对应COM口，115200波特率，8位数据位、无校验、1停止位，协议FireWater。
输出形式为`0.0,0.0,...,120.0,15000,2,0,0.0`等20项数字加换行。
启动阶段有说明文字；进入循环后遥测行只含数字。相机无新帧时不会持续发送遥测。

| 通道（从1开始） | 内容 |
|---|---|
| 1–4 | 左前、右前、左后、右后实测速率；当前全为0，表示反馈不可用 |
| 5–8 | 四轮目标线速度指令，cm/s |
| 9–12 | 四轮PWM占空比指令，百分比；当前限制±20 |
| 13 | 中线偏差err，像素 |
| 14 | 自转角速度指令omega，deg/s |
| 15 | 陀螺仪Z轴角速度，deg/s |
| 16 | 前进速度指令vx，cm/s |
| 17 | 视觉处理耗时，微秒 |
| 18 | 状态：0空闲、1编码器模式起步、2运行、3停车 |
| 19 | 停车原因：0无、1斑马线、2出界、3按键、4堵转（当前关闭） |
| 20 | 横移速度指令vy，cm/s（默认0） |

## 从summer-smartcar理解麦轮

你之前的舵机车是“电机负责前进，舵机改变前轮方向”。
这里没有舵机：四个麦轮的转速组合，直接决定车体前进、侧移或旋转。
轮缘斜装的小滚子允许侧向滚动，四轮产生的运动分量可以相互抵消或叠加。

车体坐标：x向前，y向左，omega逆时针为正。轮位顺序固定为：

```text
             车头
       左前FL     右前FR
       左后RL     右后RR
             车尾
```

以下“正转”指软件归一后的推动车辆前进方向，不是从同一观察方向看到的顺/逆时针。
默认轮组布局必须与工程逆运动学相符。

| 运动 | 左前 | 右前 | 左后 | 右后 |
|---|---|---|---|---|
| 前进 | + | + | + | + |
| 后退 | − | − | − | − |
| 左移 | − | + | + | − |
| 原地左转 | − | + | − | + |

原地左转时，左侧后退、右侧前进；前进中左转时，把这个旋转分量叠加到四轮前进分量，
右侧目标高于左侧。右转反过来。横移目前未启用。

## 当前控制链路

```text
MT9V03X灰度图
  → Otsu二值化、底部连通滤波、搜左右边界、十字补线
  → 中线与固定前瞻窗口（当前中心55行，范围45～65）
  → err = 中线列坐标 − 画面中心
  → 转向omega、前进vx、横移vy（默认0）
  → 麦轮逆运动学，得四轮目标速度
  → 临时开环：每轮PWM = 目标速度 × 0.10，限制±20%
  → DIR + PWM控制四个电机
```

视觉外环仍然通过摄像头反馈纠偏。暂时关闭的是编码器构成的电机速度内环，
因此轮速不会被精确控制。目标120cm/s并不意味着实车已经跑到120cm/s。

2026-09-30源码审查确认：动态前瞻开关定义晚于使用它的`#if`，当前未编译生效。
更完整的逐函数解释、实际生效参数及已复现问题见同目录`控制链条逐函数审查.md`。

图像每帧更新一次，名义约50Hz；电机输出与IMU采样每5ms更新一次（200Hz）；
按键每10ms扫描一次（100Hz）。`printf`只在主循环发送，不放在中断里。

### 视觉偏差怎么决定转向

`err>0`表示赛道中线在画面右侧，需要向右纠偏，omega应为负；
`err<0`表示赛道中线在画面左侧，需要向左纠偏，omega应为正。
这个判断建立在摄像头朝前、图像未水平镜像的情况下。

当前转向计算为：

```text
omega = −(0.60×e + 0.004×e×|e| + 0.30×(e−上帧e)) − 0.08×gyro_z
```

| 项 | 意义 |
|---|---|
| 一次P | 偏得越多，纠偏越强 |
| 二次P | 大偏差时进一步加强纠偏 |
| D | 根据偏差变化趋势修正动作 |
| 陀螺阻尼 | 抵消当前旋转趋势，减轻回正过冲 |

像素偏差在±2以内归零，最终omega限制在±120deg/s。
这是视觉控制器产生的角速度指令，不是目标角速度与实测角速度构成的完整跟踪PID。
IMU目前只读取角速度，没有融合姿态角，所以也不会锁定某个绝对车头角度。

### 速度与四轮分配

直道规划120cm/s，深弯80cm/s，中间随|err|增大线性降速；加速做平滑，减速立即响应。
横移`vy = −err × ctl_lateral_gain`，当前增益为0。

逆解中的旋转分量`r = omega(rad/s) × (轴距+轮距)/2`，将单位统一为cm/s后：

```text
左前 = vx − vy − r     右前 = vx + vy + r
左后 = vx + vy − r     右后 = vx − vy + r
```

例：当前轴距150mm、轮距160mm，前进100cm/s并左转90deg/s，vy=0：
旋转分量约24.35cm/s，左侧两轮目标75.65，右侧两轮124.35。
无编码器时映射为约7.6%和12.4%PWM；实际下发到电机的百分比会取整。
这些是运动学指令与临时映射结果，实际速度随电池、电机负载和地面变化。

### 发车与停车

当前：上电初始化→IDLE，KEY_1→RUNNING，KEY_2或视觉事件→STOP→清输出→IDLE。
斑马线第2次上升沿停车，连续3帧出界停车，沿用summer-smartcar的事件方式。
停车是PWM清零后的机械滑停，不保证立即停住，也无法给出制动距离。

## 编码器到货后怎么恢复

接好并标定四路编码器后，将`config.h`中的`ENCODER_ENABLE`改为1，再编译下载。
恢复后速度内环按实测轮速计算每轮PID，起步为40%PWM，达到180cm/s或1秒超时后切入正常运行，
停车恢复为零目标速度制动，堵转检测恢复。
该起步阈值高于当前120/80的正常目标，正式上车前需要结合实车重新调节。
`ENCODER_ENABLE`只恢复代码路径；电机方向、编码器方向、每米脉冲数和PID必须重新验证。
WiFi单独由`WIFI_SPI_ENABLE`控制，恢复编码器不要求恢复WiFi。
