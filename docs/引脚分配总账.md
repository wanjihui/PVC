# 引脚分配总账与选择依据

> 本文回答两个问题：**每个引脚是怎么定下来的**，以及**有没有冲突**。
> 数据由 `python tools/check_pins.py` 自动核对（读 `config.h` 与库头文件的真值，不是抄注释）。

---

## 一、结论速览

- **32 个引脚，零重复占用**（另有 CSI 摄像头的 12 个脚由库固定，见第五节）
- 其中 **28 个是"抄"来的，不是"选"的**——见第二节的来源追溯
- 我真正做的引脚决策只有 **5 个**，见第三节
- 有 **2 个硬约束**是配置过程中撞出来的，见第四节

## 二、引脚从哪来（来源追溯）

| 功能 | 引脚 | 来源 | 谁定的 |
|---|---|---|---|
| 电机 1~4 DIR/PWM | C9/C8, C7/C6, D2/D3, C10/C11 | `E3_04_drv8701e_double_motor_contro_demo` 的**代码区**宏定义 | 逐飞 |
| 编码器 1~4 A/B | C0/C1, C2/C24, C3/C4, C5/C25 | `E2_01_encoder_quadrature_demo` 的代码区宏定义 | 逐飞 |
| IMU（ICM20602，SPI4） | SCK=C23 MOSI=C22 MISO=C21 CS=C20 | `zf_device_icm20602.h` 写死 | 逐飞 |
| 摄像头（MT9V03X，CSI） | TX=C29 RX=C28 VSY=B22 PCLK=B20 D0~D7=B31..B24 | `zf_device_mt9v03x.h` 写死 | 逐飞 |
| WiFi SPI | SCK=D12 MOSI=D14 MISO=D15 CS=D13 INT=B17 RST=B16 | `zf_device_wifi_spi.h` 写死 | 逐飞 |
| 按键 ×4 | C15 C14 C13 C12 | `zf_device_key.h` 的 `KEY_LIST` | 逐飞 |
| 调试串口 | TX=B12 RX=B13 | `zf_common_debug.h` 默认 | 逐飞 |

**这些引脚不能随便改**，因为它们和逐飞主板/核心板的**硬件走线**绑定了：
买了逐飞的主板，编码器接口、电机信号接口、无线模块插座在 PCB 上就连到这些脚。
改软件引脚 = 必须自己飞线。

## 三、我实际做的 5 个引脚决策

| 决策 | 选择 | 依据 |
|---|---|---|
| **用 CSI 接口还是 FLEXIO 接摄像头** | **CSI** | 官方文档原话："如果只使用一个摄像头，请使用 CSI 接口的、使用 CSI 接口的、使用 CSI 接口的（重要的事说三遍）" |
| **屏幕用不用** | **不用** | WiFi SPI 与 IPS200 并口 7 个引脚完全冲突（见第四节） |
| **遥测串口选哪个** | **UART6（TX=B2 RX=B3）** | 查库确认 B2/B3 空闲、未被摄像头/电机/编码器/WiFi 占用。原 summer 工程也用 UART6 |
| **电机→轮位怎么映射** | M1=左前 M2=右前 M3=左后 M4=右后；第 1 块驱动板管前两轮，第 2 块管后两轮 | 走线最顺（同侧两轮放一块板）。**但这是可换的**，见 `docs/电机接线对照表.md` |
| **编码器 4 的 A 相用 C5 还是 C4** | **C5**（`QTIMER2_ENCODER2_CH1_C5`） | 见下方"文档纠错" |

### ⚠ 官方文档的一处错误（我核对时发现）

官方《RT1064智能车推荐引脚分配》里"正交解码"一节写：

```
正交解码
LSB:C0 DIR:C1
LSB:C2 DIR:C24
LSB:C3 DIR:C25      ← 这里错了
LSB:B18 DIR:B19
```

第三行 `LSB:C3 DIR:C25` 与第二行的 C24 凑不成一对硬件解码器，而且 **C3 已被第二行/示例的
ENCODER_3 占用**——同一个引脚不可能同时给两个编码器。

查库头文件的枚举才是真值：

```c
QTIMER2_ENCODER1_CH1_C3   = 4 * 2,     // ENCODER_3 用的就是这个
QTIMER2_ENCODER1_CH2_C4   = 4 * 2,     // C4 与 C3 同属 QTIMER2 子模块1
QTIMER2_ENCODER2_CH1_C5   = 5 * 2,     // C5 与 C25 同属 QTIMER2 子模块2
QTIMER2_ENCODER2_CH2_C25  = 5 * 2,
```

所以 **ENCODER_3 = C3/C4、ENCODER_4 = C5/C25**（与 `E2_01` 示例代码一致），
官方文档那行应是把 `C3/C4` 误写成了 `C3/C25`。本工程按代码区实现。

## 四、配置过程中撞出来的 2 个硬约束

### 约束 1：WiFi SPI 与 IPS200 屏幕 7 个引脚全撞

| WiFi SPI | IPS200 并口 | |
|---|---|---|
| SCK `D12` | `D0..D7` 里的 D12 | ✗ |
| MOSI `D14` | D14 | ✗ |
| CS `D13` | D13 | ✗ |
| INT `B17` | B17 | ✗ |
| RST `B16` | B16 | ✗ |
| MISO `D15` | D15 | ✗ |

**不是"可能冲突"，是物理上不能共存**。所以"移除屏幕 + 用 WiFi SPI 传图"是同一个决定。
来源：逐飞 `E6_09` 示例原话"使用高速 WiFi SPI 模块时无法使用并口屏幕（因为引脚有共用）"。

### 约束 2：官方的 PWM 引脚列表被 WiFi 占掉一半

官方推荐可用作 PWM 的引脚只有 8 个：

```
D0  D1  D2  D3  D12  D13  D14  D15
              └──────┬──────────┘
        D12/D13/D14/D15 已被 WiFi SPI 占用
```

剩下的 `D0 D1 D2 D3` 里，`D2/D3` 又被用作电机 3 的 DIR/PWM。

> **结论：要 4 路 PWM，就必然不能用官方的 PWM 脚列表。**

这也正是逐飞自己的 `E3_04` 示例改用 **C6 / C8 / C11** 的原因——C 口同样有 PWM 能力，
只是不在官方"推荐"列表里（因为 C4~C15 有下面的注意事项，见约束 3）。
本工程 4 路 PWM 用的是：`C8`（模块1）`C6`（模块0）`D3`（模块3）`C11`（模块2），
**已在库的 `pwm_channel_enum` 中确认都是合法 PWM 通道**。

### 约束 3：C4~C15 的官方注意事项（不是禁区）

官方原文（注意是"尽量"和"不要用作输入"）：

```
C4 至 C15 尽量不要使用
如果需要使用的话 C4 至 C15 尽量不要用作输入
如果确实需要使用请参考库例程 15-Burn Fuse Demo，操作后将不再具有上述的限制
```

本工程在 C4~C15 上的用法：**12 个引脚**

| 引脚 | 用途 | 方向 |
|---|---|---|
| C4, C5 | 编码器 3B / 4A | 输入（QTIMER 硬件解码） |
| C6, C7, C8, C9, C10, C11 | 电机 DIR / PWM | **输出** |
| C12~C15 | 按键 | 输入（库已处理消抖） |

判断：
- 6 个电机信号全是**输出**，符合"不要用作输入"的建议；
- 6 个输入（4 路编码器 + 4 个按键——C4/C5 是编码器、C12~C15 是按键）确实落在"尽量不要用作输入"范围，
  但逐飞自家示例就是这么接的（`E2_01` 编码器用 C0~C5、`E6_09` 按键用 C12~C15），
  实际使用中未见问题；
- 若日后遇到**上电偶发不启动**或编码器/按键异常，第一嫌疑就是这里，
  解法是跑一次库例程 `E16_burn_fuse_demo` 烧写 fuse 解除限制。

> 另注：官方还提到"使用 FLEXIO 接口的摄像头时，务必保证内核启动后才给摄像头供电"。
> **本工程用的是 CSI 接口，该注意事项不适用**。

## 六、如果引脚冲突了怎么办

`python tools/check_pins.py` 会在发现重复占用时报出退出码 1 并列出冲突引脚。
修改引脚的三种情况：

1. **改我 config.h 里的软引脚**（电机 DIR/PWM、编码器 A/B、VOFA 串口）
   → 直接改 `code/config/config.h`，然后**必须**重跑 `check_pins.py` 确认没撞到别人。
   注意：电机 PWM 的新引脚必须在库的 `pwm_channel_enum` 里存在；编码器的必须在
   `encoder_channel1_enum` / `encoder_channel2_enum` 里存在（且 A/B 同属一个 QTIMER 子模块）。

2. **改库里写死的引脚**（IMU、WiFi SPI、按键、摄像头）
   → 改对应 `libraries/zf_device/zf_device_*.h` 的宏。改 WiFi 目标 IP 也在这类里（见 README）。

3. **换板的注意事项**
   → 这些引脚是逐飞**主板走线**决定的，换板/飞线后必须重新核对本表。
