# 电机接线对照表 —— 两块 DRV8701E 驱动板 → 四个麦轮

> 用途：照着这张表插线，并逐通道确认"哪个物理轮子 = 软件里的哪个轮位"。
> 引脚来源：逐飞官方示例 `E3_04_drv8701e_double_motor_contro_demo` 的**代码区定义**，
> 与本工程 `code/config/config.h` 的 `MOTOR1~4_DIR/PWM_PIN` 逐条一致（已核对）。

---

## 一、每个 DRV8701E 通道需要几根线

逐飞的 DRV8701E 模块是**单路**驱动板（一块板驱动一个电机），每路只需 **2 根信号线**：

| 信号 | 作用 | 接到主控的什么引脚 |
|---|---|---|
| **DIR** | 方向：高/低电平决定电机正转还是反转 | 普通 **GPIO 输出** |
| **PWM** | 速度：占空比决定转多快（本工程 17kHz） | **PWM 输出**引脚 |

所以「一块板两个电机」= 两块板 = **4 组 (DIR, PWM)** = 8 根信号线 + 公共 GND。

> 注意：DIR 是**电平**信号，PWM 是**脉冲**信号，两者用途不同、不能互换。
> 板子上的丝印若写 `DIR`/`PWM`（或 `PH`/`EN`），按丝印接即可。

---

## 二、板子 → 轮位 → 引脚 对照表

本工程俯视布局：

```
        车头
   M1(左前)  M2(右前)      ← 第 1 块板（通道 1、2）
   M3(左后)  M4(右后)      ← 第 2 块板（通道 3、4）
        车尾
```

| 轮位 | 软件名 | 建议用哪块板/通道 | DIR 引脚 | PWM 引脚 | PWM 通道名 |
|---|---|---|---|---|---|
| **左前** | `WHEEL_FL` / M1 | 第 1 块板 通道1 | **C9** | **C8** | `PWM2_MODULE1_CHA_C8` |
| **右前** | `WHEEL_FR` / M2 | 第 1 块板 通道2 | **C7** | **C6** | `PWM2_MODULE0_CHA_C6` |
| **左后** | `WHEEL_RL` / M3 | 第 2 块板 通道1 | **D2** | **D3** | `PWM2_MODULE3_CHB_D3` |
| **右后** | `WHEEL_RR` / M4 | 第 2 块板 通道2 | **C10** | **C11** | `PWM2_MODULE2_CHB_C11` |

每个通道还要与主控共 **GND**（信号地必须共地，否则电平不成立）。

> **哪块板管哪两个轮子可以自由选**，上表只是建议（同侧两轮放一块板，走线最顺）。
> 真正决定软件行为的是"哪个物理轮子接在哪组引脚上"。
> 接完线后**必须**做下面的第 4 节确认，否则方向补偿表会填错。

---

## 三、为什么引脚是成对的

看引脚号能发现规律：`C9/C8`、`C7/C6`、`D2/D3`、`C10/C11` 都是**相邻的两个引脚**，
并且每对落在同一个 PWM 子模块上（`PWM2_MODULE1`、`MODULE0`、`MODULE3`、`MODULE2`）。
这是逐飞为"电机信号排线"专门留的布局，两块板的灰排线直接插主板对应接口即可。

同一子模块的两个引脚里，一个被用作 PWM、另一个用作普通 GPIO（DIR）——
技术上两脚都能输出 PWM，这里只是就近配对。

---

## 四、上手必做：确认"物理轮 = 软件轮位"

**这一步不能跳过**，因为接线顺序和你的摆放习惯不可能和示例完全一致。

做法：临时在 `main()` 的 `while(1)` 之前，一次只给一个通道加电，看哪个轮子转：

```c
/* 临时测试：逐个通道验证（每次只留一行，编译下载后观察） */
system_delay_ms(2000);
motor_set_wheel(WHEEL_FL, 20);   /* 应该只有【左前】轮转 */
system_delay_ms(2000);
motor_set_wheel(WHEEL_FR, 20);   /* 应该只有【右前】轮转 */
system_delay_ms(2000);
motor_set_wheel(WHEEL_RL, 20);   /* 应该只有【左后】轮转 */
system_delay_ms(2000);
motor_set_wheel(WHEEL_RR, 20);   /* 应该只有【右后】轮转 */
motor_stop();
```

四种情况与处理：

| 现象 | 说明 | 怎么改 |
|---|---|---|
| 转的轮子就是软件标注的那个 | 接线正确、`MOTORx_DIR_INVERT` 正确 | 不用改 |
| **转错了轮子**（比如命令 FL 却是右前转） | 板子/通道与轮位的对应关系接反了 | **改接线**，或把 `config.h` 里那组的引脚宏对调 |
| 轮子对了但**转向相反** | 该电机极性反了 | 把 `config.h` 的 **`MOTORx_DIR_INVERT` 改成 1**（不要改接线） |
| **四个轮子一起转** | 两块板接到了同一组引脚 | 检查排线是否插到了同一接口 |

### 麦轮的方向基准

四轮都调好后，要求的最终状态是：

- 命令四轮 **正占空比** → 车**向前**走（四个轮子都朝前转）
- 命令**纯前进** `mecanum_inverse(vx>0, 0, 0)` → 四轮同速同向
- 命令**纯横移** → 对角成对反号（左前/右后 一组，右前/左后 另一组）
- 命令**原地逆时针自转** → 左侧两轮后退、右侧两轮前进

> 这三条方向特征可以用 `python tools/verify_mecanum.py` 在没有硬件时先跑一遍确认公式，
> 上车后再用上面第 4 节的单通道测试确认物理接线。

## 五、编码器（同样 4 路，别和驱动线搞混）

编码器是**独立**的 4 组 A/B 相，走 QTIMER 硬件正交解码，与电机驱动线没有对应关系：

| 轮位 | 编码器索引 | A 相 | B 相 |
|---|---|---|---|
| 左前 | `QTIMER1_ENCODER1` | C0 | C1 |
| 右前 | `QTIMER1_ENCODER2` | C2 | C24 |
| 左后 | `QTIMER2_ENCODER1` | C3 | C4 |
| 右后 | `QTIMER2_ENCODER2` | C5 | C25 |

确认方法：架空车，用手**同向**转动四个轮子，`Debug` 菜单看 `spd` 的符号是否一致。
某个轮子符号相反 → 改 `config.h` 的 `ENCODERx_INVERT`。

---

## 六、常见坑

1. **不共地**：驱动板与主控必须共 GND，否则 DIR 电平不成立、电机乱转或不转。
2. **驱动供电与主控供电**：电机的功率电源（电池正负极）接驱动板的电源端子，
   **不要**从主控板取电给电机。
3. **DIR 接成了 PWM 引脚**：能出电平也能动，但速度不可控；反之 PWM 接成普通 GPIO 则电机只会全速或停。
   按第 2 节的表逐脚核对。
4. **麦轮装反**：四个麦轮必须满足"对角轮辊子方向一致"。
   横移方向整体相反时，用 `config.h` 的 `MECANUM_Y_SIGN = -1.0f` 整体修正，
   **不要**去改单个电机的 `MOTORx_DIR_INVERT`（那会同时破坏前进与自转的方向一致性）。
