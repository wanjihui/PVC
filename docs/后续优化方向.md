# McarPVC 后续优化方向

更新日期：2026-09-30。

本文记录当前代码与 CYT4BB7_Air 的 IMU 实现对比，以及适合本项目的后续改进路线，包括姿态、航向控制、惯导和融合定位。当前代码基线为 `ecd9aa2`，参考仓库为 `national-2026` 分支的 `f4154ef`。下面的优化项均为待实施建议，不代表已经改入代码或通过实车验证。

配套阅读：[CYT4BB7_Air 仓库概括与学习路线](CYT4BB7_Air_阅读概括.md)、[当前临时模式与麦轮控制说明](当前临时模式与麦轮控制说明.md)、[硬件模块验证方案](硬件模块验证方案.md)。

## 1. 当前项目处于什么阶段

- 主控为 RT1064，IMU 为 ICM20602。
- IMU 与电机输出按 5 ms 周期更新，即 200 Hz；视觉决策随摄像头出帧，约 50 Hz。
- 编码器尚未接入，`ENCODER_ENABLE=0`；四轮使用限幅开环输出，暂时没有实测轮速反馈。
- `WIFI_SPI_ENABLE=0`，使用 printf 经 UART1 向 VOFA FireWater 输出 20 通道，约 25 Hz。
- 当前 IMU 输出用于转向控制的是 Z 轴角速度，没有计算四元数、横滚角、俯仰角或航向角。

当前 IMU 处理流程：

```text
读取陀螺仪
    ↓
Z 轴减零偏 → 换算为 °/s → 安装方向修正
    ↓
一阶低通
    ↓
gyro_z → 视觉纠偏中的转向阻尼
```

“角速度”表示现在转得多快，例如 30°/s；“航向角”表示当前朝向或相对起始方向转了多少度。当前实现属于角速度处理，完整姿态解算是后续可增加的能力。

## 2. 与 CYT4BB7_Air 的对比概括

| 比较项 | 当前 McarPVC | CYT4BB7_Air | 对麦轮车的学习价值 |
|---|---|---|---|
| 数据使用 | 读取三轴角速度，主要处理 Z 轴 | 三轴角速度、三轴加速度 | 增加静止判定和姿态估计的输入 |
| 标定 | Z 轴采样 200 次求平均零偏 | 三轴零偏及加速度计校准 | 学习标定有效性检查，先保证输入可靠 |
| 静止判断 | 根据车辆状态开关零偏跟踪 | 根据角速度、加速度和连续样本判断 | 区分停车命令与物理停稳 |
| 滤波 | Z 轴一阶低通 | 陀螺仪陷波/低通、加速度低通 | 按实际振动与控制延迟选择参数 |
| 姿态输出 | 暂无姿态角 | Mahony 四元数与欧拉角 | 为定角转弯、车头方向保持和倾斜判断提供基础 |
| 控制反馈 | 视觉纠偏叠加 gyro_z 阻尼 | 姿态角环、角速度反馈环 | 学习目标与实际值比较、串级控制 |
| 调试方法 | 当前 20 通道串口遥测 | 原始/滤波数据、标定状态、振动分析等 | 用记录数据定位问题，减少盲调 |

六轴 Mahony 使用重力方向帮助修正横滚和俯仰；只有陀螺仪和加速度计时，航向角没有绝对参考，仍会长期漂移。作者报告的低漂移效果依赖其硬件与标定，不能直接视为本项目的性能保证。

对于当前平地循迹，优先提高 gyro_z 的可靠性与转向反馈质量；需要指定角度转弯、横移时保持车头方向或坡道姿态时，再增加 Mahony。

## 3. 第一优先级：静止判定与零偏跟踪

### 当前问题

当前发车时关闭零偏跟踪，避免把真实转向当成偏置，这个处理应保留。

无编码器停车路径在撤掉 PWM 后，会立即恢复零偏跟踪并进入 `CAR_IDLE`。车可能仍在滑行或旋转；此时学习零偏，会把部分真实角速度吸收到偏置中，影响下一次发车。代码位置：`code/control/control.c` 的 `control_stop_poll()`，以及 `code/imu/imu.c` 的 `imu_update()`。

### 后续方向

- 以“收到停车命令”作为允许检查静止的前提，不直接等同于停稳。
- 结合三轴角速度、加速度模长与波动，连续满足条件一段时间后，再允许零偏更新。
- 编码器到货后，加入四轮速度接近零的条件；IMU 的静止判据只能辅助判断，匀速平移不一定能被 IMU 识别。
- 一旦检测到运动，立即停止更新零偏；检测使用的信号应避免被正在学习的零偏过度影响。
- 阈值和等待时间根据本车静止、抖动和慢转数据确定，不照搬飞机参数。

### 验证方法

记录停车后的角速度、零偏和跟踪状态；比较真正静止、停车后余转、手动慢转三种场景。应能看到静止时偏置缓慢收敛，真实旋转期间偏置不追随运动变化。

## 4. 第一优先级：标定与初始化有效性

### 当前问题

`imu_calibrate_gyro()` 将 200 次 Z 轴读数直接平均，未判断采样期间是否移动或波动过大。上电过程中碰动车体可能污染标定结果。

`main.c` 中 IMU 初始化失败后只输出提示，后续初始化和运行流程仍继续，控制层缺少明确的数据有效状态。

### 后续方向

- 对标定样本计算均值与波动，运动时丢弃本次结果并重新标定，设置合理的超时和失败状态。
- 增加三轴陀螺仪与加速度采集，为有效性判断提供输入。
- 增加 IMU 初始化、标定和数据有效状态，控制层根据有效状态决定是否允许发车、使用或降级角速度反馈。
- 后续姿态解算再考虑加速度六面校准；椭球校准和参数保存可以作为更晚阶段的内容。

当前 `imu_update()` 只调用 `icm20602_get_gyro()`；`imu_get_acc_raw_z()` 只是返回缓存变量。增加加速度判断前，必须补上实际采样，不能把未刷新的缓存当作新数据。

### 验证方法

分别测试静止上电、标定中轻碰车体、IMU 初始化失败。检查有效标定能被接受，受扰标定会被重试或拒绝，失败状态可被控制层明确识别。

## 5. 第二优先级：数据记录与滤波

先建立可比较的数据记录，再决定是否更换滤波器。

建议记录原始 gyro_z、去偏后角速度、滤波角速度、当前零偏、静止判定、转向目标和控制输出。当前 25 Hz 遥测适合观察低频控制趋势，不能直接用来分析高频机械振动。

高频记录时应减少通道或调整传输方式与波特率，控制好带宽；不要在 200 Hz 中断里使用阻塞 printf。记录时间戳，确认实际采样间隔和是否丢样。

后续滤波方向：

- 将滤波参数明确表示为截止频率，并与实际采样周期对应。
- 检查 IMU 硬件低通与软件采样的配合，关注噪声和反馈延迟的取舍。
- 比较静止、电机运转、转弯时的原始与滤波数据；仅在确认振动频带后考虑陷波。
- 改变更新频率时，同步调整滤波、静止判定持续时间及积分周期。

CYT4BB7_Air 的默认 IMU 更新为 1000 Hz，默认陀螺仪陷波为 300 Hz。McarPVC 当前采样为 200 Hz，奈奎斯特频率为 100 Hz，不能直接使用该 300 Hz 陷波设置。

验证时同时观察波形噪声和转向响应：输出更平滑，但反应明显变慢，也不一定是更好的控制结果。

## 6. 第二优先级：编码器与转向反馈

编码器到货后，先完成四轮方向、计数换算、轮径、底盘尺寸及轮速 PID 调试。当前速度指令到 PWM 的开环映射不能保证实际车速，姿态算法也不能替代轮速反馈。

当前转向大致为：

```text
旋转指令 = 视觉纠偏量 − 陀螺仪阻尼项
```

后续可设计为：

```text
视觉误差 → 目标车体角速度
                    ↓
        与实测 gyro_z 比较，进行反馈修正
                    ↓
       vx、vy、旋转控制量 → 麦轮运动学
                    ↓
           四个车轮速度环 → PWM
```

例如目标左转 30°/s、实测只有 10°/s，应根据角速度误差进行反馈修正。具体实现需要定义控制器输出的单位和含义，协调车体角速度反馈与四轮速度环，避免把飞控的推力混控输出直接当成轮速。

验证方法：在不同前进速度和左右转向下比较目标、实测角速度与四轮速度。先建立稳定的基础反馈，再逐步增加速度和视觉纠偏力度。

## 7. 第三优先级：Mahony 与航向控制

为定角转弯、倾斜判断和后续惯导建立姿态基础，接入完整六轴解算。

适用需求包括原地转指定角度、横移时保持车头方向，以及倾斜或坡道姿态判断。实现前应完成三轴采集、单位转换、标定、稳定周期与异常数据处理。

移植要点：

- 保留 ICM20602 的驱动，适配算法输入接口；ICM42688 驱动不能直接替换本车驱动。
- 明确角速度使用 °/s 还是 rad/s、加速度使用 g 还是 m/s²，避免重复换算。
- 统一三轴坐标和旋转正方向后再送入算法，不能只翻转输出 yaw。
- 参考项目规定俯视顺时针为正，本车规定左转为正，需要处理坐标差异。
- 使用实际 5 ms 更新周期，不能照搬 1 ms；滤波、静止判定和增益需要重新验证。
- 测试慢速旋转，避免静止判定或死区吞掉有效运动。

接入航向控制后的概念结构为：

```text
目标航向 − 当前相对航向
           ↓
       目标角速度
           ↓
       角速度反馈
           ↓
       四轮运动控制
```

六轴 yaw 可作为短时间相对转角参考。需要长时间保持准确航向时，应进一步考虑视觉等外部参考；赛道中线位置误差本身也不能直接当作绝对航向测量。

验证方法：静止倾斜测试横滚/俯仰，再使用独立角度参考测试左右定角旋转、重复转弯误差和静止漂移。作者原平台上的结果只能作为参考，性能以本车测试为准。

## 8. 第四优先级：惯导与融合定位

### 目标与能力边界

加入惯导方向，目标是估计小车相对起点的位置 `(x, y)`、航向 `yaw`、前进和横移速度，逐步支持定距移动、横移保持车头方向、定角转弯和简单路径跟踪。

需要分清三个阶段：

| 阶段 | 输入与处理 | 输出与用途 |
|---|---|---|
| 姿态估计 | 六轴 IMU、Mahony | 姿态与相对航向，为后续估计提供坐标变换 |
| 航向辅助轮式里程计 | 四轮编码器速度 + IMU 航向 | 短距离相对位置；适合作为第一版落地目标 |
| 辅助惯导/融合定位 | IMU 姿态和加速度预测 + 编码器速度 + 可用的外部观测 | 姿态、速度、位置联合估计，改善单一传感器的不足 |

Mahony 本身不会输出位置或速度；编码器加陀螺仪的第一版也应准确称为航向辅助轮式里程计。后续把去重力后的加速度用于运动预测，再结合观测修正，才能逐步形成辅助惯导。

### 为什么不能只对加速度连续积分

纯惯性积分的基本流程是：

```text
三轴角速度 → 姿态
                 ↓
三轴加速度 → 坐标变换与重力补偿 → 线加速度
                 ↓
              积分得速度
                 ↓
              积分得位置
```

加速度零偏、姿态误差造成的重力残留、振动和采样时间误差都会积累。纯惯导可以作为短时实验，但不能直接预期这块 ICM20602 长时间独立提供准确位置。[VectorNav 对惯导积分与误差来源的说明](https://www.vectornav.com/resources/detail/what-is-an-ins)

作为简化示例：如果水平加速度只残留 `0.01 m/s²` 的恒定偏差，且初始速度和位置正确，10 秒后的单轴位置误差就是 `0.5 × 0.01 × 10² = 0.5 m`。这只是数学示例，不是本车的实测指标。

### 阶段 A：先完成数据和姿态基础

- 按硬件验证方案确认 IMU、四个编码器和电机通道有效，完成方向与计数标定。
- 采集三轴角速度和加速度，确认量程、单位、安装变换、时间戳和更新周期。
- 完成零偏、加速度校准、静止判定和 Mahony，记录姿态与静止漂移。
- 定义局部参考系：起点为位置零点，初始车头方向为 X 正向，左侧为 Y 正向，逆时针航向为正。
- 纯平地阶段可先使用 Z 轴角速度得到短时相对航向；明显倾斜时使用完整三轴姿态变换。

当前没有编码器反馈，也没有加速度与完整姿态处理，不能把目标轮速或 PWM 当成已经测得的车体速度。

### 阶段 B：第一版相对位置估计

用四轮实测线速度推得车体系的前进、横移和旋转速度，再利用 IMU 航向变换到局部参考系，积分得到位置。

按本工程的麦轮逆运动学，在默认符号约定、理想接触且无打滑条件下，正运动学可推导为：

```text
vx_body = (vFL + vFR + vRL + vRR) / 4
vy_body = (-vFL + vFR + vRL - vRR) / 4
wz_wheel = (-vFL + vFR - vRL + vRR) / (4k)
k = (轴距 + 轮距) / 2
```

这里四轮速度用 m/s，尺寸用 m，所得 `wz_wheel` 为 rad/s；如果调整运动学符号开关，正运动学也应同步对应。四轮速度输入来自编码器，不使用指令值。

令局部航向为 `psi`，则：

```text
vx_local = cos(psi) × vx_body - sin(psi) × vy_body
vy_local = sin(psi) × vx_body + cos(psi) × vy_body
x += vx_local × dt
y += vy_local × dt
```

这一步先验证估计轨迹和实际轨迹是否一致，不急于增加复杂滤波器。轮速估出的角速度可与 gyro_z 对比，帮助定位方向、尺寸或打滑问题，但它也不是绝对航向参考。

### 阶段 C：增加惯性预测与观测修正

在第一版里程计稳定后，再考虑平面 EKF 或其他适合的融合方法：

```text
IMU 角速度、去重力线加速度 → 高频运动预测
                                   ↓
四轮编码器的 vx、vy、wz → 速度观测修正
                                   ↓
确认静止时的零速度条件 → 静止修正
                                   ↓
可用的视觉或其他外部观测 → 位置/方向修正
                                   ↓
输出 x、y、yaw、速度、可信度与有效状态
```

可先围绕平面位置、速度、航向和陀螺仪零偏设计小规模状态，再根据需要加入加速度零偏。融合模型、噪声参数和执行频率应依据本车日志与运行耗时确定，不照搬飞控参数。

关键约束：

- 麦轮可以正常横移，必须保留 `vy`；不能套用双电机转向车的 `vy=0` 约束。
- 加速度用于预测之前，先按完整姿态完成坐标变换并去掉重力；不能只把一个固定值从传感器 Z 轴扣掉就认为得到水平加速度。
- 静止修正要综合停车状态、轮速和 IMU；匀速平移不能只靠加速度判定。
- 麦轮打滑时，轮速可能不等于车体速度，特别需要验证横移和旋转场景；观测异常时降低对应数据的信任程度。
- 同一份编码器数据推得的位置、速度和角速度存在关联，不应都当成相互独立的观测重复使用；同样注意 Mahony 与原始 IMU 的数据关联。[robot_localization 的传感器融合配置说明](https://raw.githubusercontent.com/cra-ros-pkg/robot_localization/rolling-devel/doc/configuring_robot_localization.rst)
- 编码器与 IMU 融合仍属于相对估计，不能保证长期位置和航向误差有界。EKF 不会自动产生缺失的绝对观测。

### 阶段 D：引入外部参考，再接导航控制

根据实际任务选择外部参考，例如已知地标或视觉定位、经过标定的地面光流、UWB 等；室外有条件时再考虑 GNSS。先明确观测究竟提供位置、速度还是方向，以及精度、时延和失效条件，再加入融合。

当前 MT9V03X 循迹中线偏差只能提供赛道相关的局部信息，不能直接作为完整 `(x, y, yaw)` 或绝对航向输入。需要相机标定、观测模型及足够的场景约束，才能成为定位信息。

在估计有效后，再让“目标位置与当前估计位置的差”产生 `vx、vy`，让航向误差产生角速度目标，最终经麦轮分配和四轮速度环执行。对估计设置有效状态与可信度，数据丢失、明显跳变或不可信时退出导航动作。

可将短时丢线时的运动预测列为后续实验用途，但目前的连续出界停车保护应保留；以后也需限定允许预测的时间、距离和退出条件。

### 验证与阶段验收

以独立的地面标记、尺子和角度参考作为真值，不能只看滤波器自己的输出是否回到起点。

| 测试 | 观察指标 |
|---|---|
| 静止 60 秒 | 航向、速度和位置漂移；是否误判运动 |
| 前进/后退固定距离 | 距离误差、横向误差、往返误差 |
| 左右横移固定距离 | 横移距离与航向保持，左右结果是否对称 |
| 左右转 90°/180° | 独立角度误差、原地旋转时的位置误差 |
| 已知尺寸的方形路线 | 实际回到起点的偏差与估计轨迹 |
| 不同速度、地面和轻微打滑 | 误差变化、观测降权是否合理 |

分别记录纯轮式里程计、轮速加 IMU 航向、进一步融合后的结果，比较同一测试条件下的误差。先取得可重复的基线，再根据用途设定验收精度，不提前承诺厘米级定位。
