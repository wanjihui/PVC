本轮按用户要求加入速度规划，针对上一份CSV中150cm/s过弯、残余转动及轮速差回收滞后的问题。没有改前瞻45、视觉转向PID、陀螺系数0.30、横移0.10、四轮PID或图像算法；独立角速度PID与缺行偏差放大修订仍未执行。

## 实际代码链条

主循环新图像 → `control_update()` → 原 `omega_calc()` 得到视觉P/二次P/帧差分需求 → `curve_update_frame()` 在陀螺叠加之前取绝对值判弯。因此出弯陀螺反向阻尼不会被当成紧弯。一个差分尖峰不会立即分弯，需两张连续新帧；两帧间隔超过100ms重置确认计数。

直道可确认普通弯或紧弯，普通弯可升级紧弯；同一弯中不从紧弯反复升速到普通弯。只有出弯条件全部满足连续200ms才回直道。这样较保守，可能让出弯后的直道前段保持100一段时间，可根据数据再调整恢复门槛。

5ms PIT中 `control_tick_isr()` 采最新IMU → 更新500ms起步包络 → `curve_speed_tick()` 做弯速限幅和加减速率限制 → 原陀螺阻尼/omega限幅 → 原横移 → `mecanum_inverse(vx,vy,omega)` → 四轮Target → 原速度PID。

直道起步仍0→150、500ms。弯中起步受120/100上限约束；已到较高速度后识别弯道按250cm/s²下降，不瞬间跳到100。线上巡航调低时也按减速率过渡；若设80，弯道不会把规划反而抬到100或120。

只降低车体前进分量vx，不按比例缩小四轮目标，不减掉四路固定PWM，不缩放转向/横移；所以降速不会同时削弱所需轮速差。真实减速度仍受轮速环、电机和轮地接触影响，不能把目标变化率当作实测车身加速度。

K2仍立即关闭速度环并清PWM，不等待减速坡；初始化、停车、重新K1均清弯道等级/确认/稳定计时。仅视觉循迹启用规划，独立轮速调试模式保留原固定速度与起步。原堵转目标门限120会漏掉100弯速，已改为60cm/s；仍要求四轮实际都低于25、连续15个检测帧才停车。

启动日志追加 `[READY] CURVE` 显示速度、需求门槛和加减速率。CSV原148字节及字段保持：`vx_cmd_cms` 是平滑后的前进目标，完整起步后应看到150、120、100附近的段及过渡。新增弯道参数本轮只在config调节，没有扩充上位机23项GET/SET；在线cruise_cms仍是直道上限。
