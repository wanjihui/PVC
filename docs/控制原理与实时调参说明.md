# McarPVC 控制原理与实时调参说明

本文对应 2026-10-09 本轮修订后的源码。运行方式是上电等待 K1，K1 开启视觉循迹与四轮速度闭环，K2 停车；前进目标在 500 ms 内由 0 升至 150 cm/s，直道和弯道使用同一前进目标，不进行弯道降速或自适应前瞻。WiFi 参数、IMU、图像和必要日志继续上传，不由 K1/K2 开关控制。本文说明的是代码行为与调参依据，软件测试不能代替车辆上的效果验证。

## 1. 先分清四个量

| 量 | 来自哪里 | 单位及意义 | 是否直接控制电机 |
|---|---|---|---|
| `g_vis.err` | 图像中线与画面中心的差 | px；正值表示赛道在画面右侧 | 否 |
| `vx / vy / omega` | 控制层 | 前进、向左横移 cm/s；向左自转 deg/s | 否 |
| `Motor_PID[i].Target` | 麦轮逆运动学 | 每个轮子的目标圆周线速度 cm/s | 否 |
| `OutCmd` / 下发 `duty` | 每轮速度 PID | 有符号占空比百分数，正值已归一为车辆前进方向 | 是 |

与以前双电机加舵机的车相比，视觉层仍回答“赛道相对车身偏在哪里”。以前主要靠舵机改变前轮转角，再由驱动轮推动小车沿曲线走；现在没有舵机，转向指令转换为左右轮速差，横移指令转换为两组对角轮的轮速差。四轮各自跟踪运动学分配的目标，而不是把同一占空比同时写给四轮。

轮速闭环保证轮子转得接近目标；它无法单独保证车身沿赛道中心移动。麦轮打滑时，编码器可以显示目标已实现，而车身实际转向不足。这就是还需要视觉反馈、IMU 观测和实跑数据的原因。

## 2. 三条执行路径分别在哪里运行

### 2.1 主循环：每个新图像计算一次视觉指令

`main` 调用 `app_init()`，然后反复调用 `app_poll()`。正常模式下 `app_poll()` 的顺序是：

1. `app_buttons_poll()` 消费按键事件，调用发车或停车状态函数。
2. `app_vision_poll()` 检查相机与新帧，调用 `vision_capture_frame()`、`vis_deal()`；随后根据事件决定停车，并调用 `control_update()` 与堵转检查。
3. 网络断开且车辆处于停车状态时，按重试间隔重新初始化网络。
4. `wifi_poll(elapsed_ms, new_frame)` 准备最新参数包及到期的图像快照，`wifi_poll_log(elapsed_ms)` 推进异步传输、读取命令、处理参数回复和日志。
5. 根据 `APP_MAIN_LOOP_DELAY_MS` 做末尾延时。这个延时不是速度环定时源。

没有新图像时，不重复对旧图像计算视觉差分项。正在传输的图像使用独立快照，后续视觉处理不会改写它。上传启动间隔为 100 ms，即目标 10 fps；完整接收帧率还取决于 SPI、无线丢包和主循环推进速度。车上视觉计算频率与电脑看到的完整图像帧率是两个量。

### 2.2 5 ms PIT_CH0：传感器、运动学、四轮速度闭环

`PIT_IRQHandler()` → `pit_handler_200hz()` → `app_tick_isr()`，每拍依次执行：

1. `elapsed_ms += 5`，更新板上时间。
2. `encoder_pit_callback()` 读取四路硬件累计计数，以本次减上次得到 5 ms 增量。
3. IMU 初始化成功后 `imu_update()` 读取六轴数据，更新姿态与控制用角速度。
4. 允许驱动时 `control_tick_isr()` 推进起步速度斜坡，叠加陀螺反馈，分配四轮目标。
5. `Speed_PID_Crtl()` 读取四轮实际速度，计算各轮 PID 并写占空比。

在两次视觉更新之间，视觉角速度指令保持上一帧的值；IMU 反馈、起步斜坡和四轮速度环仍每 5 ms 更新。WiFi 发送不放在这个中断中。

### 2.3 10 ms PIT_CH1：按键扫描

`pit_handler_100hz()` → `app_keys_isr()` → `buttons_scan_isr()`。K1 的事件由主循环消费；K2 经 20 ms 按下确认后直接在扫描路径停车，不需要等图像或 WiFi 返回。主循环之后补记停车日志。

上电时 `motor_init()` 输出 PWM=0，`control_init()` 把状态设为 `CAR_IDLE` 并关闭速度环。只有 K1 进入 `CAR_RUNNING`。启动时重置 PID、上一帧视觉误差、斜坡时间、视觉状态和里程；停止时关闭内环、清目标/累计输出并立即写 PWM=0。在线调参协议没有发车指令，应用参数不会自行发车。`cruise_cms=0` 只把前进分量设为零，不会退出 RUNNING；视觉自转和横移仍可存在，所以它不能替代 K2 停车。

## 3. 图像怎样变成 `g_vis.err`

### 3.1 固定同一帧，避免灰度图与线条错帧

CSI 中断经库回调置位 `mt9v03x_finish_flag`。`vision_capture_frame()` 短暂关闭 CSI IRQ，将完整的 `188×120` 灰度图复制到 `vision_gray`，清完成标志，再恢复 CSI IRQ。此处没有关闭全部中断，PIT 仍可采样。

算法读 `vision_gray`，上传灰度背景也取它。`vision_monitor_payload()` 在灰度图后逐行附加左边界、右边界、中线和补线标志；因此上位机叠线展示的是算法实际处理的这一帧。它不是发送一张二值图替代原图。

### 3.2 `vis_deal()` 的实际顺序

1. **阈值与二值化。** `compute_otsu()` 每隔 10 帧更新一次阈值，灰度直方图采用全屏 4×4 下采样，阈值钳制在 20～235；更新时采用 `0.3×新阈值+0.7×旧阈值`。首个缓存阈值产生前使用 128。整幅图中大于阈值为白色 255，其余为黑色 0。
2. **原始出界预检。** `out_of_bounds_check()` 在连通滤波之前检查底部赛道窗口。底行无白色种子时，滤波可能把上方白色清掉，所以不能先滤波再依据结果判出界。
3. **底部连通滤波。** `filter_bottom_connected()` 保留与底部种子连通的白色区域，当前处理底部 110 行，以减小背景白色干扰和计算量。
4. **斑马线检测。** `zebra_detect()` 更新检测状态。斑马线优先于出界：检测到斑马线时，不同时报告丢线。上升沿才生成 `VISION_EVT_ZEBRA`；原始出界产生 `VISION_EVT_LOST`。
5. **清边界并搜边。** `sweep_boundaries()` 写入左右边界及真实边界标志，并保存补线前的原始边界。
6. **十字判断与补线。** 仅有候选或斜入候选时执行 `cross_detect()` 和 `cross_repair()`；补线修改边界坐标，并记录补线标志。补线区段由邻近有效边界拟合并外推，检测状态还会跨帧确认和保持。它是在恢复轨迹，不是在决定弯道速度。
7. **中线与误差。** `pho_center()` 根据最终边界计算中线，再计算固定前瞻窗口的偏差。
8. 导出轨迹，记录处理耗时、相邻帧间隔、处理帧数和事件，返回事件给 app。

`app_vision_poll()` 对第二次斑马线上升沿、连续 3 帧丢线执行停车。堵转检查另要求前进目标达到 120 cm/s、四轮实际速度全低于 25 cm/s，连续 15 个视觉帧才停车；按实际视觉帧数计时，并不是单独固定 0.3 s 定时器。

### 3.3 搜边、缺边和补线为什么会影响控制

`longest_white_col()` 找到底部向上的最长白列作种子。底行向左右扩展，以连续两个黑像素确认边界，减少单像素噪声影响。之后自底向上逐行跟随上一行边界，起点失效时退回种子；单边丢失可用最近有效路宽外推另一边，双边失效还会区分真正黑区与十字白区，并保留候选给十字补线。

`pho_center()` 先对边界做三点平滑，跳过无效值和过大的跳变。双边有坐标就取 `(左+右)/2`；双边都是真边界时更新真实路宽；只有一边则用最近真实路宽外推中线；两边都没有时尝试该行白色像素重心。没有足够白像素则标记中线无效。最后对中线再平滑。

所以 `err` 不一定每一行都来自“真实左右边界中点”，也可能来自外推、补线或白色重心。先看上位机的原始灰度背景与最终线条是否正确，再调控制增益；增益不能修正错认的赛道。

### 3.4 固定前瞻窗口和误差放大

`asc_far` 同步自 `ctl_preview_row`，默认 55，钳制到 20～100。计算窗口是中心行上下各 10 行，即默认 y=45～65。图像行号越小越远，越大越靠近车头。

代码从近行往远行累加：近端权重 1，远端逐渐增至 5，对有效中线列计算：

```text
err = Σ[(该行中线列 - pho_center_x) × 行权重] / Σ[有效行权重]
```

边缘不可靠的列和无效行不参与。之后如果有效行不足，再乘 `min(20/有效行数, 2.5)`。注意窗口含端点共有 21 行，但代码用于这个补偿的 `theo_rows` 是 `y_near-y_far=20`，因此不是完整 21 行就一定放大；有效行小于 20 才放大。没有任何有效行时，保留上一帧误差。

这解释了为何某些缺边帧的 `err` 可以明显增大：除了赛道真实偏移，还有有效行减少后的放大。出现误差突跳时，应检查补线与有效行，不能直接归因于车头摆动。

## 4. 视觉误差怎样变成转向

`control_update()` 在每个新图像后缓存两个量：视觉角速度 `vision_omega_command` 和横移 `vision_vy_command`。真正分配轮速是在 5 ms 中断中。

### 4.1 `omega_calc()` 的公式及符号

默认死区为 2 px。严格满足 `-2 < err < 2` 才把 e 置零；恰为 ±2 仍参与。

```text
delta = e - err_last
omega_visual = -[ 1.6×e + 0.012×e×|e| + 0.3×delta ]   deg/s
err_last = e
```

负号来自 `CONTROL_IMAGE_TURN_SIGN=-1`：图中赛道偏右时 e>0，需要右转，即 omega<0。图中赛道偏左则相反。符号是坐标关系，不是力度参数，不应为修正“转向弱”随意反号。

线性 P 控制普通误差的响应；二次 P 对所有非零误差都参与，在大误差时占比增加，没有“超过 60 px 才启用”的门槛。D 项是相邻图像误差的差值，**没有除以帧间时间**，也不是四轮速度 PID 中的 D。偏差快速增大时，它增强同方向转向；偏差回落时可以减弱已有指令。帧率改变或边界跳变会改变它的作用，不能笼统理解成固定物理阻尼。

横移缓存为 `vy=-err×lateral_gain`，默认增益 0，所以目前只通过自转纠偏。横移使用原始 `g_vis.err`，没有套用 `omega_calc()` 的死区。

### 4.2 实际使用的是角速度负反馈，不是航向角 PID

倒装 IMU 的原始 `gz_dps` 已由用户实测：左转负，右转正。`imu_update()` 控制分支通过 `IMU_MOUNT_YAW_SIGN=-1` 取反，并采用 `IMU_GYRO_LPF_ALPHA=0.5` 低通滤波，使控制用角速度为左正右负。上位机原始 `gz_dps` 不随这个控制符号一起修改。

`control_tick_isr()` 每拍执行：

```text
omega_out = clamp(omega_visual - 0.08×gyro_control, -240, +240)
```

因此车辆已左转时，从左转指令中减去一定量，抑制继续旋转；已右转时同理减弱右转指令。这有助于抑制摆头，但增益过大也会削弱正常入弯。不能把它称为独立的角速度目标误差 PID：代码没有计算 `omega_target-gyro` 后运行一套角速度 PID，也没有用 `yaw_target-yaw` 做航向角闭环。

姿态 yaw/roll/pitch 是观察量，当前循迹不以 yaw 角为转向反馈。由于倒装，静止 roll 约 ±180°并不等于小车真的侧翻。

### 4.3 用当前参数算两次完整分配

以下是假设误差暂时稳定、`delta=0`、已完成起步、横移 0 的计算例子，不是对某帧实跑数据的复现。

**赛道偏左 e=-40 px：**

```text
omega_visual = -[1.6×(-40)+0.012×(-40)×40] = +83.2 deg/s
若控制角速度已为 +60 deg/s：omega_out = 83.2-0.08×60 = +78.4
等效力臂 = (L+W)/2 = (20+18)/2 = 19 cm
rot = 78.4×π/180×19 ≈ 26.00 cm/s
FL=RL=150-26.00≈124.00 cm/s
FR=RR=150+26.00≈176.00 cm/s
```

右侧更快，产生左转。这里控制 +60 对应上位机原始 gz 大致为负值，但零偏分支及滤波会使两者不必逐样本精确互为相反数。

**赛道偏右 e=+60 px：**

```text
omega_visual = -[1.6×60+0.012×60×60] = -139.2 deg/s
若控制角速度已为 -80 deg/s：omega_out = -139.2-0.08×(-80) = -132.8
rot≈-44.04 cm/s
FL=RL≈194.04 cm/s；FR=RR≈105.96 cm/s
```

左侧更快，产生右转。如果这一帧 e 从 40 跳到 60，则 `delta=20`，还会增加 -6 deg/s 的视觉差分响应。

### 4.4 起步斜坡控制的是目标速度，不是直接占空比

K1 后每个 5 ms 拍将斜坡时间增加 5 ms：

```text
vx = cruise_cms × min(累计起步时间/ramp_ms, 1)
```

默认首拍前进目标 1.5 cm/s，250 ms 时为 75 cm/s，500 ms 时为 150 cm/s。电机占空比由速度环计算，未必线性增加。视觉转向、IMU 反馈和轮速 PID 从第一拍就有效；代码只对 vx 做斜坡，不把 omega 和 vy 同比例压低。所以起步大偏差仍可能产生很大的左右轮速差，极端情况下某侧会反转，不能理解成四个电机都以同样斜坡向前启动。

## 5. 麦轮运动学怎样分配四轮目标

`motor.c:mecanum_inverse()` 中先把角速度从 deg/s 转成 rad/s，再使用完整轴距和轮距计算等效力臂。当前 L=20 cm、W=18 cm，故：

```text
rot = omega×π/180×19 ≈ 0.33161×omega   cm/s
FL = vx - vy - rot
FR = vx + vy + rot
RL = vx + vy - rot
RR = vx - vy + rot
```

轮序始终为 FL 左前、FR 右前、RL 左后、RR 右后。使用用户确认的辊子方向：俯视车头朝上，FL/RR 为左上—右下，FR/RL 为左下—右上。`MECANUM_Y_SIGN` 和 `MECANUM_W_SIGN` 是整体运动方向修正；电机方向补偿则用于统一每个电机正占空比的实际前进方向，两者用途不同。

omega=0、vy=0 时四轮同一目标；纯左转时左侧减速、右侧加速；向左横移时 FL/RR 减速、FR/RL 加速。增加转向强度是增大左右目标差，不是统一加大四轮占空比。

240 deg/s 限幅意味着最大旋转分量约 79.59 cm/s。vx=150、vy=0 时，对应某侧约 70.41、另一侧约 229.59 cm/s。理想无滑移中心曲率半径 `R=v/omega_rad` 约 35.81 cm；这只是运动学算式，轮子跟踪能力、地面抓地、载荷和视觉延迟都可能使实际半径更大，不能保证某个弯必过。

## 6. 编码器、每轮 PID 与最终占空比

### 6.1 实际速度的换算

当前采用 1024 线编码器、1 倍频硬件计数。车轮轴 68 齿齿轮带动 30 齿编码器齿轮，车轮一圈对应编码器 `68/30` 圈。使用周长 19.5 cm：

```text
counts_per_cm = 1024×1×(68/30)/19.5 ≈ 119.02906
Actual = 5ms计数增量 / counts_per_cm / 0.005   cm/s
```

16→68 的电机传动改变电机轴到轮轴的速度比例；因为此处已从轮轴到编码器轴计算，不再额外重复乘 68/16。四轮的编码器反向配置把向前转动统一为正。硬件计数器运行时不清零，代码用本拍减上拍并处理计数回绕，避免“读取后清零”的丢脉冲窗口。

计数/cm、轮子位置、方向和周长是反馈标尺，不是为了弯道更灵活随意调整的增益。标尺错了，即使 PID 把数值追得很漂亮，真实速度仍会错。

### 6.2 增量式 PID 的真实公式

`Speed_PID_Crtl()` 将各轮编码器速度写入各自 `Actual`，开启状态下依次调用 `PID_INC_Update()`：

```text
e0 = Target - Actual
Δu = Kp×(e0-e1) + Ki×e0 + Kd×(e0-2e1+e2)
Out = clamp(上一拍Out + Δu, -100, +100)
若 Target>Actual：OutCmd = Out + Kff×(Target-Actual)
否则：OutCmd = Out
OutCmd 再限幅到 ±100
更新 e2=e1，e1=e0
```

默认各轮 Kp=0.10、Ki=0.001、Kd=0、Kff=0，是四套独立 PI。Ki 已是每 5 ms 一拍的离散系数，代码不会再乘 0.005。持续轮速误差 20 cm/s 时，单拍积分增加 0.02 个占空比百分点，理想累计一秒可增加约 4 个百分点，实际误差会随着响应变化。

Kp 是增量式写法：误差跳增 20 时，本拍比例增量为 2 个百分点；之后误差保持 20，比例增量不继续累加，积分项继续作用。它与“每拍把 Kp×误差一直累加”不同。`OutDeltaMax` 的单拍限幅机制虽保留，初始化值为 0，当前没有启用单拍占空比变化限制，不能宣称存在独立打滑保护。

源码历史上把 Kff 叫速度前馈，实际是 **仅在 Target>Actual 时添加的单边误差比例补偿**，不是根据目标速度建立的 `a×Target+b` 基础占空比。默认关闭，调大可以增强加速补偿，但减速一侧不会对称得到补偿；不要把它当作已标定的电机模型。

### 6.3 占空比怎样落到硬件

`Speed_PID_Crtl()` 将 `OutCmd` 强制转换成 `int16`，小数向零截断，再调用 `motor_set_wheel()`。因此控制内部可以是浮点数，但实际写 PWM 的占空比以整数百分数变化。

`motor_set_wheel()` 根据每轮方向补偿处理符号，钳制到 ±100，正负决定 DIR 电平，绝对值转换成底层 PWM 计数。PWM 载波频率 17 kHz，内环更新 200 Hz，两者不是同一频率：17 kHz 是电驱动开关频率，200 Hz 是重新决定占空比的频率。

车辆转向弱时，先看“想让轮子怎样转”和“轮子实际有没有这样转”：

- omega 指令太小 → 视觉增益/前瞻/陀螺抑制可能是原因。
- omega 长时间卡在 ±240 → 转向上限已成为约束；提高 Kp 不能突破它。
- 四轮 Target 差很大但 Actual 差跟不上 → 优先查内环动态响应和输出限幅。
- Actual 已接近 Target，但原始 gz 经符号归一后仍很小 → 考虑打滑、轮子受力、几何或测量标尺，继续加 PI 不一定改善车身转向。

## 7. 参数集中管理与上位机实时调整

### 7.1 三处职责

`code/config/config.h` 是重新编译、重新上电时的默认值入口。`control.c` 与 `pid.c` 保存运行中的参数实体，`control_params.c` 集中登记 23 项在线参数的名字、范围和修改约束。符号、几何、编码器标尺、采样周期和停车保护阈值不开放在线修改。

上位机 `06 实时调参` 页显示“编辑值”“车辆确认值”和状态。编辑框里的数字或导入的本地方案不等于车上已生效；只有车辆回复匹配的确认，才能标记已应用。在线修改只改 RAM，不写 Flash；重启恢复 config 默认值。调出满意参数后，应记录并写回 config，重新编译固化。

### 7.2 23 项在线参数

| 键名 | 默认值 | 允许范围 | 单位/作用 | 调大的主要代价 |
|---|---:|---:|---|---|
| `cruise_cms` | 150 | 0～200 | 前进目标 cm/s，直弯同速 | 纠偏时间变短，轮速差余量和抓地要求增加 |
| `ramp_ms` | 500 | 100～2000，5 的整数倍 | 起步 vx 斜坡时间 ms，仅停车可改 | 更长起步更平缓，但达到巡航更慢 |
| `preview_row` | 55 | 20～100 整数 | 前瞻中心行；数值小看远 | 调小可能更早入弯，也更受远处缺边和透视影响 |
| `deadband_px` | 2 | 0～10 | 视觉误差死区 px | 小偏差被忽略更多，可能偏到一定程度才纠正 |
| `omega_kp1` | 1.6 | 0～3 | 线性转向增益 `(deg/s)/px` | 过大会左右摆动，追随噪声 |
| `omega_kp2` | 0.012 | 0～0.03 | 二次转向增益 `(deg/s)/px²` | 大偏差或补线跳变时更易突然满转向 |
| `omega_kd` | 0.3 | 0～2 | 相邻视觉帧差分增益 | 对边界跳变、帧率变化更敏感 |
| `omega_max_dps` | 240 | 30～360 | 最终自转指令限幅 deg/s | 两侧轮速差和滑移风险增加；不代表能达到该角速度 |
| `gyro_kd` | 0.08 | 0～1 | 控制角速度减项比例，无量纲 | 转向变钝，正常弯道旋转也被压制 |
| `lateral_gain` | 0 | 0～1 | 偏差到横移比例 `(cm/s)/px` | 改变对角轮目标，视觉/滑移耦合更复杂 |
| `kp_FL / kp_FR / kp_RL / kp_RR` | 各 0.10 | 各 0～0.5 | 每轮即时轮速误差补偿；占空比百分点/(cm/s) | 噪声、占空比及轮速振荡 |
| `ki_FL / ki_FR / ki_RL / ki_RR` | 各 0.001 | 各 0～0.01 | 每 5 ms 一拍的误差累计系数 | 过冲、饱和恢复慢、负载变化时拖尾 |
| `kd_FL / kd_FR / kd_RL / kd_RR` | 各 0 | 各 0～0.1 | 离散误差二阶差分系数 | 编码器量化噪声被放大；初调保持 0 |
| `ff` | 0 | 0～0.1 | Target>Actual 时的误差附加项 | 单边补偿不对称，容易加速过猛或顶到限幅 |

表中三行四轮增益各代表 4 项，总数为 10+12+1=23。允许范围是协议约束，不是所有值都适合这辆车。

### 7.3 PC→车辆→确认的完整路径

先在 `01 调参` 启动接收，包含日志端口 8082；在 `06` 填写车辆 WiFi 模块 IP 与模块接收端口（当前模块本地端口 6666，不是电脑监听 8081）。点击“读取车辆参数”后获取当前 RAM 值；每项编辑后点击应用。

PC 发出的 ASCII UDP 命令为：

```text
MCAR GET 123 ALL\n
MCAR SET 124 omega_kp1 1.7\n
```

`\n` 表示实际换行结束符，不是手动输入反斜线和字母 n。模块接收 UDP，SPI 异步驱动从模块取回接收字节放入 FIFO。`wifi_poll_log()` 每圈以有限长度读 FIFO，`wifi_command_bytes()` 按换行拼出命令；因此 SPI 分片与 UDP 分包不同也不需要假设一读就是完整命令。

`wifi_command_line()` 校验前缀、请求编号和字段数，把 SET 交给 `control_param_set()`：检查键名、数值范围、有限性、整数条件、5 ms 步长；`ramp_ms` 必须停车。成功时在短临界区写参数、同步四轮 PID 增益，前瞻同时更新 `asc_far`。不清当前积分/累计输出、不重置误差历史、不改变 K1/K2 状态，因而大幅在线改增益仍可能产生输出跳变。

回复通过日志缓存发送到电脑 8082：

```text
[PARAM] 124 OK omega_kp1 1.7
[PARAM] 124 ERR RANGE
[PARAM] 124 ERR STOP_FIRST
```

GET 对 23 项分别回复 OK，最后发送 `[PARAM] 123 DONE`。`TuningClient.feed_line()` 检查来源 IP、请求编号、参数键和值；GET 必须收齐全部项且收到 DONE 才完成。请求初次发送后每约 1 s 重试，最多发送 3 次；旧请求或不匹配确认不会覆盖较新的编辑。超时代表“不能确认是否执行”，不是“确定没执行”，应重新读取。

重复 SET 是对同一参数赋同一值，不会增加速度或叠加增益。连接超时、发送对象切换和检测到车辆重启会使确认值失效。导入/导出仅管理 PC 本地方案，不自动写车，不自动发车，也不自动写 Flash。

8081 参数、8082 日志/确认、8083 图像是电脑三个不同的接收通道；模块命令端口是车辆一端的接收地址。分端口让固定二进制参数、文本行和分片图像各走自己的解析器，避免把命令回复当浮点数或把灰度图当日志。

## 8. 怎样调出不同能力，及每一步看什么

### 8.1 先看正确性，再看力度

先确认上传的中线确实落在赛道中央、补线能跨过缺边区域、前瞻窗口有合理有效行。如果图中线条已错，先修视觉，不提高 P 去追错线。确认左/右转符号，以及 FL/FR/RL/RR 对应实物。

数据分为起步、稳定直行、入弯、弯中、出弯和人为拦车段分别看。板上时间优先由 `samples×0.005 s` 估计，或者用明确的板上时间字段；电脑 UDP 接收时间会抖动和批量到达，不宜直接差分 yaw 得瞬时角速度。低频遥测的 enc 是对应采样拍增量，不代表两个电脑包之间累计的所有计数。

以前“转向达成率 73%”不能据此直接决定加多少增益。旧一轮剔除起步后的四轮平均相对目标偏差约 +4.4%、−2.3%、−0.6%、−0.7%，但平均绝对动态误差仍约 11～14 cm/s；它说明还要分析动态跟踪，不能概括为全部轮子稳定偏慢 15%～20%。旧数据不代表本轮新参数的实跑效果。

### 8.2 车身转向指令不足：优先调视觉线性 P

在边界正确、omega 未限幅、轮速跟踪合理时，如果车头入弯慢，先只调 `omega_kp1`。以当前 1.6 为基线，单轮试跑增加约 0.1～0.2，保持其他参数不变，比较同一个弯的误差增长、入弯峰值和出弯摆动。减小会更柔和，过小会迟迟转不过来；过大可能直道左右蛇行，入弯虽然快但出弯过头。

### 8.3 已限幅：调上限，不能再靠无限加 P

若入弯 omega 多次卡在 ±240，而实际四轮响应及抓地仍合理，可一次提高 20～30 deg/s，比较限幅持续时间、车身角速度和轮速差。如果 Actual 跟不上 Target 或 PWM 已限幅，提高上限只是在要求电机完成更难的动作。

保持150直弯同速时，急弯能力受速度与允许角速度共同约束。当前没有自动降速替你弥补几何与抓地极限；若实际赛道要求超过能力，应明确修改目标速度方案，而不是暗中恢复弯道降速。

### 8.4 普通误差已正常，只有大误差弱：再调二次 P

`omega_kp2` 每次小改约 0.001～0.002。e=20 时，0.012 的二次贡献是 4.8 deg/s；e=60 时为 43.2 deg/s。所以它适合在保留直道/小误差响应的同时增强大偏差，但对缺边放大的 err 同样生效；图像突跳时增大它会突然打满转向。

### 8.5 出弯摆头：区分视觉差分与实际旋转反馈

若误差回落但车身仍明显继续旋转，可小幅增加 `gyro_kd`，如 0.08→0.10，观察是否减少过冲及是否让正常入弯变迟缓。若同方向转向总是偏钝，也应检查它是否抑制过强。它没有保持特定 yaw 的能力。

`omega_kd` 根据相邻帧偏差变化作用：可用较小步长 0.05 调整，但必须看边界跳变和实际视觉间隔。把它加大可能提前响应增长的误差，也可能把噪声直接变成尖峰转向。它不保证单独就能消除摆头。

### 8.6 入弯总是太晚：调前瞻，不先改所有增益

`preview_row` 从 55 向 50、45 逐步调小，能看更远并提前形成偏差；代价是远处赛道可能更窄、遮挡更多，十字和补线影响更明显。向 60、65 调大更关注近处，可能稳一些但入弯更晚。它是固定行号，不对应固定厘米距离，改变相机角度或安装高度也会改变实际前瞻距离。

### 8.7 Target 已变化，Actual 跟不上：分别调各轮 PI

先看具体哪一轮、哪种加/减速段，而不是四轮一起翻倍。

- 实际速度响应慢、没有持续振荡，先把该轮 Kp 由 0.10 小增到 0.11～0.12，比较上升和下降响应；过大则占空比/轮速振荡。
- 响应形状合理，但长期存在稳定偏差，Ki 可由 0.001 小增至 0.0011～0.0012；过大会过冲且在限幅后恢复慢。
- 持续饱和不是“积分还不够”的证据，先确认负载、可达到速度和供电。
- Kd 初调保持 0，避免对 5 ms 编码器量化变化放大。
- ff 先保持 0，确认 PI 后再独立试验。它只强化某一种误差符号，不能代替四轮一致性与真正的目标速度前馈标定。

先比较目标与实际速度是否跟踪，再看 raw gz 归一后的车身运动是否实现。对倒装 IMU，车头左转时 `gz_dps` 为负是正常的，控制中反馈是正。

### 8.8 横移和起步属于独立能力

目前 `lateral_gain=0`，先调好自转与轮速。以后如需麦轮横移贴线，再单独增加横移增益并检查对角轮目标和轨迹；横移会改变控制行为，不能把它当作无代价的转向增强项。

延长 `ramp_ms` 会降低前进目标增加速度，能减轻起步负载突变；当前要求仍是 500 ms。它只改善起步阶段，不直接解决巡航时急弯不足。保持每次只改一组有明确依据的参数，保存车上确认值和相同赛道的采集数据，才能判断改动有效在哪里。
