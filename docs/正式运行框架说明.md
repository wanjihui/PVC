# app运行框架说明

2026-10-07：默认恢复视觉循迹，车体前进目标固定150cm/s，直弯同速。保持当前四轮PI与K2中断停车，不增加固定PWM起步、变速或自适应前瞻。实跑步骤与CSV字段见[视觉循迹实跑采集](视觉循迹实跑采集.md)。

## 初始化及中断

main执行一次app_init后循环调用app_poll。app_init依次建立600MHz时钟、UART、电机零输出，静止校准IMU，配置一倍频编码器，再初始化MT9V03X与GPT1微秒计时器，清控制/PID并初始化按键。上电CAR_IDLE，必须按K1发车。drive_allowed要求APP_DRIVE_ENABLE、IMU和相机就绪；相机失败最多重试3次，最终失败禁止发车并报告日志。

PIT_CH0每5ms执行app_tick_isr：更新板上elapsed_ms，读取编码器，采集/解算IMU，control_tick_isr推进0→150cm/s的500ms起步斜坡、叠加最新陀螺阻尼并分配四轮Target，再Speed_PID_Crtl读取本轮速度并产生四路独立PWM。PIT_CH1每10ms执行app_keys_isr/buttons_scan_isr：锁存K1，K2连续两拍按下约20ms在ISR内关闭速度环、清目标与PWM。ISR不打印、延时或调用WiFi。2026-10-08起运行期WiFi采用非阻塞状态机和LPSPI1 eDMA；5ms内环继续由PIT调度，仍须实车核对执行耗时。

WiFi初始化在采样PIT启动之后进行，保持停车。网络连通后请求发送启动日志，随后由主循环推进，不受K1限制；失败时缓存保留并在停车期间重试。K1由主循环执行control_state_launch，关闭内环、清PID和视觉状态、复位里程，进入RUNNING并调用control_update缓存视觉指令，最后打开内环；第一拍目标vx=3cm/s，第100拍=150cm/s。K2优先于K1，由ISR立即停车，主循环补记STOP日志。

## app_poll控制链条

1. app_buttons_poll调用buttons_poll消费锁存事件，记录启动/停止。
2. app_vision_poll调用vision_capture_frame，只短暂屏蔽CSI回调，将当前完成图像复制到vision_gray并消费完成标志；PIT仍运行。没有新图像就返回，沿用上一组轮速目标。
3. vis_deal仅读取该原始灰度快照，依次进行大津阈值缓存、二值化、原始二值图出界预检、底部连通滤波、斑马线检测、逐行搜边、十字/斜入补线、边界平滑、中线及固定前瞻偏差。原始灰度没有被二值化或叠线修改。
4. 连续3帧出界、累计第2次斑马线上升沿以及已有堵转判据可停车。这些事件不判断直弯、不调整前进速度。堵转的15帧计数跟实际处理帧走，不能当作固定300ms。
5. control_update只按新图像计算并缓存视觉omega和可选vy，不按每个5ms重复更新视觉D项；control_tick_isr每5ms用斜坡vx和最新IMU反馈合成指令，经mecanum_inverse更新四轮Target，随后速度环输出PWM。
6. 网络未就绪且停车时，每5秒允许重试入网。无论运行/停车都调用wifi_poll；IMU正常就持续提交148字节兼容参数包，停车目标/PWM清0，摄像头和日志独立发送。wifi_poll仅准备最新参数/图像，wifi_poll_log每圈推进异步事务；空日志缓存不重复发日志；参数和图像按各自周期独立发送。最后延时1ms，不代表整圈固定1ms。

## 视觉控制与轮速分配

固定前瞻55行，偏差死区2px，转向Kp1=0.60、Kp2=0.004、Kd=0.30、omega限幅120deg/s。err为赛道中线减画面中心，正值表示赛道在右侧，CONTROL_IMAGE_TURN_SIGN=-1使其产生右转omega<0。当前ctl_gyro_kd=0.08：IMU_MOUNT_YAW_SIGN=-1经实测确认，控制角速度左正右负，PIT合成omega=视觉omega-0.08×gyro_control；仍发送原始坐标IMU数据；没有添加航向保持或起步补偿。

车体x向前、y向左、omega逆时针为正。K1后vx在500ms内由0线性爬升到150cm/s，此后直弯同速；vy默认0。L=20cm、W=18cm，rot=19cm×omega(rad/s)，四轮目标FL=vx-vy-rot、FR=vx+vy+rot、RL=vx+vy-rot、RR=vx-vy+rot。弯道轮速目标不同是正常的，四轮代数平均仍为150。

四轮PI各自使用自己的Target、Actual和历史状态，Kp=0.10、Ki=0.0010、Kd=0、Kff=0，沿用上一轮直行参数；Ki已是5ms离散系数，不再次乘周期。反馈计算后输出限幅±100%，motor_set_wheel应用已验证的引脚/方向补偿，下发整数占空比。编码器保持一倍频119.02906 count/cm及已校正的FL/FR映射。

## 画面、耗时和发送门控

参数包148字节，每50ms更新候选数据；忙时只保留最新待发包，seq缺号也可能表示旧候选被替换，并非一定是无线丢包。保留108字节旧协议前缀并追加视觉偏差、车体指令、处理耗时和实际处理间隔。上位机选择“视觉循迹”预设。vis_interval_us反映真实视觉间隔；wifi_time_us是上一圈WiFi服务耗时，wifi_peak_us是上电后app_poll内通信服务的峰值。

图像每500ms最多启动一帧，一次只允许一个UDP事务在途；每圈推进一个状态步骤，事务完成后才推进分片号，分片之间仍处理新视觉帧。上传快照不被后续处理覆盖，图像帧号使用vis_processed_frames，对应CSV的vis_frames。超过600ms取消半帧；电脑800ms未组齐丢弃并保留上一完整图，UDP不重传。

MCAM v1格式2为22560字节原始灰度+480字节坐标，总23040字节，17片、末片640字节。每行[left,right,center,flags]使用最终参与控制的边界与中线，独立标记十字补线和推断边界。电脑叠加左蓝、右橙、中绿、补线紫；保存画面包含叠线。运行期SPI握手、端口切换、数据和UDP提交均采用分步状态机；SPI字节由eDMA TX30/RX31搬运。INT未就绪或DMA未完成立即返回；阶段超时200ms、事务总超时500ms均为跨主循环期限，并非等待时间。故障后退避1秒。初始化/停车重新入网仍使用同步原库，必要低频UART日志仍使用printf。软件测试不能证明实车视觉频率已改善。

K1启动电机，K2清PWM；IMU正常就持续上传参数，停车目标/PWM归零；只要主循环继续处理新图像，图像就独立上传，初始化/STOP/错误日志同样独立提交。已发出的包或电脑队列可能晚到。网络失败不阻止已就绪的传感器控制，入网重试只在停车时进行。
