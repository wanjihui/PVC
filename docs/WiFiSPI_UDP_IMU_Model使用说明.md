## 1. 先理解整个链路

```text
IMU → RT1064 采集/姿态解算 → SPI → WiFi6B21-SPI V2.0
                                      ↓ UDP / 局域网
                                电脑上的这个上位机
```

WiFi 模块负责传输字节；RT1064 负责读取 IMU、计算姿态、组织数据。电脑负责解析、显示和记录。该软件不会通过 WiFi 自动读取 IMU 寄存器，也不会把原始角速度自动解算为完整姿态。

软件有三个页面：

- **01 调参**：设置 UDP 监听、发送命令、设置二进制报文解析规则、导出 CSV、查看运行日志。
- **02 实时绘图**：显示解析值，勾选字段绘制曲线。
- **03 IMU 姿态**：根据 `roll`、`pitch`、`yaw` 旋转机体模型。

“调参”提供的是通用命令发送功能。命令名称、是否支持校准、是否允许修改参数，都由车端程序决定。

## 2. 当前 McarPVC 能不能直接连接

目前不能直接收到有效姿态数据，原因如下。

| 项目 | 当前工程 | 这个上位机需要什么 |
|---|---|---|
| WiFi 开关 | `code/config/config.h` 中 `WIFI_SPI_ENABLE=0` | 车端实际初始化并使用 WiFi 模块 |
| 网络协议 | `code/wifi/wifi.c` 建立 TCP 连接 | UDP |
| 数据格式 | 原 WiFi 业务使用逐飞助手图像/示波器协议；当前串口 `printf` 使用 FireWater 文本 | 按指定字节位置排列的二进制数值 |
| IMU 数据 | 当前主要输出 Z 轴角速度，单位 °/s | 三维模型需要横滚、俯仰、航向角，单位 ° |
| 目标地址 | `192.168.2.21:8086` | 实际电脑 IP 与软件监听端口 |
| SPI 时钟 | 驱动使用模式 3，配置 50 MHz | 官方模式 3 上限 40 MHz；模式 0 上限 30 MHz |

因此，恢复 WiFi 不能只把开关从 0 改成 1。后续还需配合 UDP、地址、二进制数据及 SPI 时钟配置。当前业务层会显式建立 TCP，单独把驱动的自动连接宏改为 UDP 也不能完成适配。

官方手册注明 V2.0 兼容旧版驱动，已有 SPI 驱动可作为适配基础。上表列的是需要处理的具体配置与业务差异。

## 3. 硬件和网络准备

### 3.1 供电与接线

官方规定模块使用 **5 V 供电**，最大电流 500 mA；SPI、INT、RST 信号电压是 **0～3.3 V**。接上匹配的外置天线，按模块丝印核对方向，再上电。

当前工程分配如下，属于代码中的引脚配置，不能代替对实际主板接口的核对：

| 模块信号 | 当前 RT1064 工程引脚 |
|---|---|
| SCK | D12 |
| MOSI | D14 |
| MISO | D15 |
| CS | D13 |
| INT | B17 |
| RST | B16 |
| 5V | 主板稳定的 5 V 电源 |
| 两个 GND | 主板 GND，共地 |
| NC | 悬空 |

如果使用逐飞学习主板的“无线模块 SPI”接口，应核对所有信号与丝印再插入。官方示例学习主板的模块 LED 朝外，其他主板以实际接口定义为准。

官方指示灯含义：红色为电源，绿色为接收，蓝色为发送。红灯亮只说明供电正常，不能据此判断已经连接热点。

### 3.2 热点与电脑地址

模块工作在 **2.4 GHz**。让模块和电脑接入可以互相通信的同一局域网，初次验证用普通路由器或 2.4 GHz 手机热点较容易排查。电脑也可以通过有线或路由器的 5 GHz WiFi 接入同一局域网。

热点名称和密码需要由 RT1064 初始化代码提供，上位机界面没有配置模块 WiFi 名称/密码的功能。

本次检查电脑 WLAN IPv4 为 **192.168.50.117**。该地址可能在更换热点或重连后变化，使用前用 `ipconfig` 再确认。不要使用未连接网卡、VPN 或虚拟网卡的地址。

模块地址由热点分配，可在模块初始化成功后的串口日志中读取，或查看路由器/热点设备列表。当前 WiFi 被关闭，所以当前程序不会打印模块初始化成功的地址。

## 4. 电脑端具体操作

以下步骤以车端已经提供匹配的 UDP 数据为前提。

### 第一步：建立监听

打开 EXE，进入 **01 调参**，在“UDP 监听”区域设置：

| 界面字段 | 建议填写 |
|---|---|
| 本机监听 IP | `0.0.0.0`，保留软件默认值 |
| 本机监听端口 | `8081`，软件默认值 |

点击 **开始监听**。`0.0.0.0` 表示监听电脑所有 IPv4 网卡，不是模块发送数据时填写的目标地址。

如果 Windows 出现防火墙提示，允许该软件在实际测试网络接收数据。监听成功仅表示电脑打开了 UDP 端口；看到“收到 UDP 报文”和非零接收帧率，才说明已有数据到达。

### 第二步：车端地址与端口对应

以本次电脑 IP 为例，双方应按下表对应：

| 位置 | 配置 |
|---|---|
| 模块传输方式 | UDP |
| 模块发送目标 IP | `192.168.50.117`，使用时重新核对 |
| 模块发送目标端口 | `8081`，与上位机监听端口一致 |
| 模块本地端口 | 例如 `6666`；这是当前工程的本地端口配置 |
| 上位机“模块 IP” | 模块实际获得的 IP |
| 上位机“模块端口” | `6666`，以车端实际本地端口为准 |

也就是：**模块发到“电脑 IP:8081”，电脑发到“模块 IP:6666”。**

软件发送区的默认 `192.168.1.100:5001` 只是示例，不能直接照抄。“模块 IP/模块端口”用于电脑发送命令；只接收数据时，它们不会决定监听结果。

### 第三步：设置姿态解析规则

软件默认规则如下，起始字节从 0 开始计数：

| 字段名 | 数据类型 | 起始字节 | 字节序 | 含义 |
|---|---|---|---|---|
| roll | float32 | 0 | little | 横滚角，° |
| pitch | float32 | 4 | little | 俯仰角，° |
| yaw | float32 | 8 | little | 航向角，° |

默认要求每个 UDP 报文至少包含 12 字节，开头依次是三个 IEEE 754 小端单精度浮点数。`little` 就是小端字节序；一个 `float32` 占 4 字节。

例如车端一次发送 `roll=10.0、pitch=-5.0、yaw=30.0`，默认布局对应这三个数的 12 字节二进制内容。发送字符串 `"10,-5,30"`、逗号分隔的 `printf` 文本，或者逐飞示波器协议包，都不能按默认规则正确解析。

驱动三维模型的字段必须命名为 `roll`、`pitch`、`yaw`，软件匹配时不区分大小写；单位必须为度。不能把 `gyro_z`（°/s）命名成 `yaw`（°）来代替姿态解算。

若数据包先有包头、时间戳或其他字段，需要按车端实际布局修改起始字节。

### 第四步：看数值、曲线和模型

1. 在日志中确认收到 UDP 报文，接收帧率大于 0。
2. 进入 **02 实时绘图**，查看解析值，并勾选要绘制的字段。
3. 进入 **03 IMU 姿态**，缓慢改变车体方向，核对横滚、俯仰、航向的变化与实际动作。
4. 如果模型方向反了，核对 MCU 的轴定义、安装方向和角度符号；模型视角按钮只改变观察视角。

软件绘图最多约 15 次/秒，不等于 IMU 的采样频率。网络接收帧率也是 UDP 报文数量，不一定等于真实 IMU 样本数量。

### 第五步：保存 CSV

在 **01 调参 → 数据保存** 填写 CSV 路径，然后点击 **保存全部解析数据**。留空时软件自动命名。导出内容包括电脑接收时间、来源 IP/端口以及解析字段。

这是导出已接收记录的操作，不是打开软件就自动持续写 CSV。首次验证可记录 10～30 秒，再导出用于比较静止抖动和转动响应。

## 5. 配合参考飞控工程时的额外注意

下载的 CYT4BB7_Air 工程中，`wifi_justfloat` 会自动把一个浮点时间戳放在数据前面。**如果**车端调用顺序是 `wifi_justfloat(roll, pitch, yaw, ...)`，则应改为：

| 字段名 | 类型 | 起始字节 | 字节序 |
|---|---|---|---|
| timestamp | float32 | 0 | little |
| roll | float32 | 4 | little |
| pitch | float32 | 8 | little |
| yaw | float32 | 12 | little |

该软件按每个 UDP 报文的固定位置取值，没有 VOFA 那样根据 JustFloat 帧尾自动拆分多帧的逻辑。若一次报文装入多帧、报文从半帧开始、姿态前还有其他字段，上表也需要调整。初次适配建议一个 UDP 报文发送一个完整固定布局样本，并在 SPI 写完后按驱动要求立即提交 UDP 发送，避免连续样本被合并。

该参考工程默认电脑端口为 `1347`、模块本地端口为 `6666`。使用它时可以将软件监听端口改为 `1347`，或统一修改车端目标端口；软件默认的 `8081` 不是硬性要求。

此外，该参考工程当前部分姿态遥测调用处于注释状态。UDP 初始化成功不代表已经在发送姿态，需核对实际执行的发送路径。

## 6. 命令发送与校准

文本模式发送原样 UTF-8 字节；勾选“十六进制”时，将 `AA 55 01` 这样的输入转成字节发送。软件**不会自动追加回车换行**，输入框里的字面量 `\r\n` 也不会自动变成 `0D 0A`。

例如参考飞控工程要求命令以 CRLF 结尾，其中只读命令 `imu status\r\n` 的完整字节为：

```text
69 6D 75 20 73 74 61 74 75 73 0D 0A
```

这只是该参考工程的协议示例，当前 McarPVC 没有对应的命令处理。软件默认二进制解析规则也不能显示此类命令的文本回复，查看文本回复需使用合适的网络调试工具。

还需注意：软件发送命令会新建一个临时 UDP socket，发送源端口不保证等于监听端口。如果对端限制发送方源端口，或者直接按命令来源端口回包，可能出现遥测能收、命令或回复异常的情况。适配时需要核对对端行为；将回复固定发到电脑监听端口，或让上位机从监听 socket 发命令，是两种可采用的实现方向。

## 7. 常见现象与排查

| 现象 | 优先检查 |
|---|---|
| 无法开始监听 | 是否重复点击开始、端口占用、是否误填模块 IP 为本机监听 IP |
| 已监听，但接收帧率为 0 | MCU 是否启用 WiFi、是否发送 UDP、电脑 IP/目标端口、同一局域网与防火墙 |
| 红色电源灯亮，仍收不到数据 | 电源灯不能证明已联网；检查串口初始化日志、热点名/密码、SPI/INT/RST 接线 |
| 收到报文，但数值异常 | 文本与二进制混用、float/int 类型不符、字节序错误、包头/时间戳造成偏移 |
| 数值有变化，三维模型不动 | 字段是否命名为 roll/pitch/yaw、是否发送的是角度 |
| 模型方向或角度不对 | 度/弧度、安装方向、坐标系、欧拉角顺序和符号 |
| 命令显示已发送，但无反应 | 模块目标 IP/本地端口、MCU 是否支持该命令、CRLF、源端口限制 |
| WiFi 初始化不稳定 | 5 V 供电能力、信号与引脚对应、天线、SPI 模式/时钟；当前 50 MHz 超出模式 3 官方 40 MHz 上限 |

## 8. 建议的首次验证顺序

1. 保持电机停转，先验证模块供电与 SPI 初始化。
2. 确认模块加入热点，记录电脑和模块的实际 IP。
3. 使用匹配的 UDP 固件发送三个已知浮点测试值，确认网络和解析规则。
4. 再替换为真实 IMU 数据。姿态解算完成前，可新增 `gyro_z` 字段看角速度曲线。
5. 完成姿态解算后，再用三维模型检查姿态方向和静止稳定性。
6. 最后加入调参/校准命令。

这些是后续实现与验证步骤，本次仅写使用说明，未执行车端改动。
