# 150cm/s视觉循迹实跑采集

2026-10-08。已恢复视觉外环，车体前进速度150cm/s，直弯同速。四轮PI沿用Kp=0.10、Ki=0.0010、Kd=0；没有新增固定PWM起步或特定轮子补偿。上电等待K1，K2清PWM，IMU兼容参数流持续，目标/占空比归零，摄像头图像不随K2停止，初始化与事件日志独立发送。

## 本次怎么采

1. 使用新版WiFiSPI_Monitor。01选择“视觉循迹”，监听IP保持0.0.0.0，端口8081参数、8082日志、8083图像，开始三路监听。
2. 编译/下载McarPVC/project/mdk/rt1064.uvprojx的nor_sdram_zf_dtcm目标。校准时保持静止；确认日志MOTOR、IMU、ENCODER、CAMERA、WIFI和READY；新版WIFI成功日志含tx=ASYNC_EDMA ch=30/31。相机或IMU初始化失败不会允许发车。
3. 赛道上K1发车；04观察原始灰度和边界。左边界蓝、右边界橙、中线绿，十字补线及推断边界紫。绿线是算法用于求偏差的中线。显示倍率只改变电脑显示尺寸，不改变原始分辨率、算法或带宽。
4. K2结束，01保存全部解析数据和运行日志；出现搜线异常时，在04保存当前画面（含叠线）并提供该帧图像。告知异常在直道、左弯还是右弯，以及开始手动拦车的大概时刻。

旧EXE只懂灰度格式1，不能显示新格式2；固件和上位机需配套更新。图像仍按500ms限频启动，理论上限约2fps，实际完整帧率受主循环、SPI/UDP切换、丢包影响。这个帧率不等于车上摄像头采集频率或视觉处理频率。

## 新CSV字段

148字节参数包保留原108字节IMU、累计enc、samples、seq及四轮target/speed/duty字段。新预设追加以下内容：

| 字段 | 单位及用途 |
|---|---|
| vis_err_px | 赛道中线相对图像中心偏差，正值为赛道在右侧 |
| omega_cmd_dps | 视觉指令减去0.08×控制角速度后的最终角速度，负值右转 |
| vx_cmd_cms | 车体前进目标，起步0→150（500ms），其后150 |
| vy_cmd_cms | 横移指令，本次默认0 |
| vis_time_us | 最近处理一帧的耗时，含处理期间中断占用 |
| vis_interval_us | 最近两次vis_deal入口间隔，含等待新帧和通信拖延 |
| vis_frames | 上电以来处理帧数；图像帧号与取快照时的此值相同 |
| wifi_time_us | 上一圈完成的WiFi服务耗时，包括参数/图像/日志；不是当前参数包发送完后的耗时 |
| wifi_peak_us | 上电以来app_poll内WiFi服务最大耗时；不含app_init入网和初次日志提交 |
| vision_event | 最近帧事件：0正常，1出界，2斑马线上升沿 |

原有enc仍为有符号累计整数计数；目标/实际轮速cm/s，占空比%。参数包按50ms更新候选，只记录最近一次200Hz内环状态，不能重建每一拍速度环。2026-10-08起发送忙时只保留最新待发候选，seq缺号也可能是候选覆盖或发送失败，不全是UDP无线丢包。

## 后续分析顺序

先判断图像中的左右边界、中线和补线是否合理，再看vis_err_px与omega_cmd_dps的方向及幅值，接着对比四轮target和speed是否跟得上，最后看duty是否饱和。直弯同速是vx固定，弯道左右轮目标不同属于正常运动学分配。

视觉即时频率可用1000000/vis_interval_us估计；较稳妥的平均频率是两条记录之间Δvis_frames/板上时间差，板上时间差可用Δsamples×0.005秒。首帧interval=0不参与计算。若原本约20000us却周期性变成40000us、60000us，结合wifi_peak_us与画面上传时刻排查通信阻塞；不能仅凭2fps上位机画面推断车上视觉只有2Hz。

2026-10-08起，WiFi上传由提交/poll状态机和LPSPI1 eDMA推进，端口切换及UDP提交也改为异步。每圈只推进一个步骤，INT忙/DMA未完立即返回；没有运行期原地等模块的循环。仍有图像快照、CRC、缓存复制、视觉计算及中断占用，初始化/停车重连和必要UART日志仍同步，因此必须用实跑数据评估改善，尚未声称达到固定50Hz视觉外环。图像限频仍为2fps，本次先消除运行期等待，暂不提升图像目标帧率。

IMU倒装及原始gz左负右正已由用户实测确认，IMU_MOUNT_YAW_SIGN=-1。ctl_gyro_kd=0.08为本轮初调阻尼，omega_cmd=视觉omega-0.08×控制角速度。控制角速度还带0.5低通，与原始gz简单取负不完全相同；gz_dps仍原样上传，不要把它直接当作与omega_cmd同号的车体角速度。

## 本轮数据判读与动作

先确认上电READY显示drive=1、closed_loop=1、vision=1、target=150.0cm/s、ramp=500ms、gyro_kd=0.080；上电不会自动发车，保持静止完成IMU校准后按K1。先跑一圈或到第一次明显异常就按K2，保存CSV、运行日志，并在搜线异常时保存含边界/补线的画面；说明直道/左弯/右弯、偏向及手动拦车开始时刻。

正常入口停车也持续生成148字节数据包，便于确认IMU与停车状态；K2复位PI，目标与PWM为0，停车的speed字段为复位状态，不能当作测得的滑行轮速。分析行驶段先以vx_cmd_cms>0分离发车/停车，再按日志剔除手动拦车段。enc是累计计数，samples在正式模式来自编码器5ms采样，停止前后继续累加；不能把它当成仅RUNNING的采样计数。IMU符号验证模式的samples来自IMU，该模式目前关闭。

本轮仅恢复正常模式、启用小陀螺阻尼并保留IMU/图像独立上传；四轮PI、视觉Kp/Kd、前瞻55行和2fps图像限频未改。软件回归覆盖起步期间陀螺负反馈、四轮PI、K2停机和停车数据/画面；未自动下载或实跑，实际阻尼与循迹参数仍须这轮数据迭代。
