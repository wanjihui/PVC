## 1. 入口、上电与初始化：main.c

源码：[main.c](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/project/user/src/main.c:52)。

### system_init，52～109行

1. `clock_init(SYSTEM_CLOCK_600M)` 配置600MHz系统时钟。启动文件在进入main前完成运行时准备，未显式赋值的静态/全局变量按C运行时清零。
2. `debug_init()` 配置UART1并注册printf底层输出；当前115200、TX=B12、RX=B13。300ms延时让外设上电稳定。
3. `mt9v03x_init()` 返回0成功。失败打印、等200ms、重试，`retry>10`退出，所以可有11次失败调用。最终失败置统一标志 `hardware_init_failed=1`；重试后成功则不置位。
4. `imu_init()` 重试并做零偏校准，最终失败打印并置同一标志。其他模块成功不会清除已经置位的故障。
5. `motor_init()` 配置四路方向/PWM，初始占空比0。编码器初始化被 `#if ENCODER_ENABLE` 排除。
6. `vision_init()` 初始化GPT1为微秒计时，供视觉耗时诊断，不负责摄像头采集或图像算法复位。
7. `control_init()` 设置初始空闲状态和输出关闭。
8. `buttons_init()` 配置四个输入按键及扫描计时单位。
9. WiFi初始化当前整段被编译开关排除。以后启用时，`wifi_init()` 返回失败也置统一标志，包括其连接流程失败。
10. 本函数不启动PIT，也不打印ready；返回main后统一检查硬件初始化故障。

`hardware_init_failed` 初始为0，任一已启用、具有失败返回值的硬件初始化最终失败置1。电机、编码器、按键、时钟等初始化接口返回void，没有提供接线或硬件就绪检测，不能据此识别这些硬件未接入。禁用模块不参与初始化与故障检查。

上电IMU校准时，电机PWM尚未初始化，但业务程序尚未给任何行驶指令。校准要求车辆静止，源码没有检测“校准期间是否移动”。

### main，114～219行

先调用 `system_init()`，紧接着、在业务主循环之前检查 `hardware_init_failed`。为1时关闭四轮PWM、打印错误，停留在100ms延时循环，不处理发车按键，修复硬件后需复位重试。为0才启动两路PIT、允许全局中断、打印ready与按键提示，然后进入业务循环。因此初始化失败的IMU不会被5ms周期中断继续读取。

`pit_ms_init(PIT_CH0,5)`、`pit_ms_init(PIT_CH1,10)`会立即启动PIT，库的 `pit_init()` 自身就使能PIT IRQ，所以两次调用都必须放在故障检查通过之后。

`frame_count`累计处理帧，不等于摄像头实际采集帧总数；`lost_count`记录本次运行连续出界事件；`zebra_rises`记录本次运行斑马线上升沿次数。

每次循环先保存 `state_before_buttons`，再调用 `buttons_poll()`。当按键把非运行状态变成RUNNING/LAUNCHING，清 `lost_count`、`zebra_rises`，避免上一轮停车计数残留。它不清 `frame_count`，遥测分频沿用累计计数。

当前无编码器分支在循环顶部处理STOP，因此手动撤PWM不依赖新图像。仍然必须等主循环有机会执行，不能把10ms按键扫描等同于10ms以内一定完成停车动作。

只有 `mt9v03x_finish_flag!=0` 才处理图像：

```c
mt9v03x_finish_flag = 0;
frame_count++;
evt = vis_deal();
```

先消费标志，再计算本帧结果。这个标志只有一位，不是帧队列；主循环慢时会合并/丢弃中间帧，也没有记录每帧真实时间戳。

运行或起步状态下的事件处理严格为：

- ZEBRA：清连续出界计数、累计一次斑马线上升沿，达到2次请求停车。
- LOST：连续计数，达到3次请求停车，名义50Hz下约60ms量级，但相位与实际帧间隔会影响实际延迟。
- NONE：清连续出界计数。
- 非运行状态：不累计终点计数，清LOST计数。

之后依次调用 `control_update()`、`control_stall_watchdog()`、遥测。事件停车在外环更新之前，因此该帧不会继续走RUNNING运动分配分支。堵转停车在外环之后，是另一个调用时机；当前堵转函数直接返回0。

`VOFA_SEND_DIV=2` 时每两帧printf一次；小于等于1时每帧发送，0并不表示关闭遥测。WiFi轮询被排除。

**缺口：**没有“距上一帧已经多久”的判断。摄像头运行中断线后，旧目标会被5ms输出分支持续使用；没有新帧也就不会累计LOST。图像停更与图像内容出界是两种不同故障。

## 2. 中断、摄像头与按键

源码：[isr.c](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/project/user/src/isr.c:28)、[buttons.c](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/code/buttons/buttons.c:22)。

### pit_handler_200hz

顺序是编码器采样（当前排除）→IMU采样→电机输出。恢复编码器后，这个顺序使本次PID使用本次刚采样的轮速。视觉、打印、状态决策没有放进该中断。

IMU的实际调用周期由 `SPEED_LOOP_PERIOD_MS` 决定，滤波/校准时间常数使用 `IMU_PERIOD_MS`。两者目前都是5ms；未来分别改宏而不改调度会产生周期不一致。

### pit_handler_100hz 与 PIT_IRQHandler

100Hz函数只调用 `key_scanner()`。CH0/CH1共用IRQ：先检查CH0并执行，再清标志，再检查CH1；CH2/CH3仅清标志，没有业务。结束 `__DSB()` 用于保证外设访问顺序。

5ms是配置周期，未测中断最坏耗时。若一次处理超过周期，不能保证每个到期事件都被独立执行。CH0长耗时也会延后同一IRQ中的按键扫描。

### CSI_IRQHandler 与实际图像缓冲

入口调用SDK `CSI_DriverIRQHandler()`，最终回调库 `mt9v03x_finished_callback()`（`libraries/zf_device/zf_device_mt9v03x.c:389`）。

库有两个188×120的DTCM缓冲：`mt9v03x_image1`、`mt9v03x_image2`。完成回调取得满缓冲地址，把 `mt9v03x_image` 指向刚完成的一份，交回另一份作为空缓冲，置 `mt9v03x_finish_flag=1`。这不是业务层的独占图像快照协议。

`vis_deal()` 的Otsu与二值化直接读全局指针。若读取期间跨过下一次帧完成，指针可能更新；处理太慢时旧缓冲还可能被重新采集覆盖。双缓冲降低冲突，但没有保证一次算法始终读同一帧。需要实测与明确的帧指针/缓冲所有权交接。

摄像头配置首先尝试SCCB，失败转UART5。UART方式注册 `camera_uart_handler` 并打开接收中断；本项目没有自己的LPUART5接收入口去调用这个回调，而库弱入口转SDK默认处理。这条兼容路径需要补齐，不能因为SCCB正常就认为UART回退已验证。

### LPUART1_IRQHandler 与 LPUART6_IRQHandler

UART1有接收字节时调用 `debug_interrupr_handler()`（当前库开关为1），把字节放入调试FIFO，然后清溢出。这里没有VOFA命令解析，因此当前上位机只能看曲线，发字节不能直接改控制参数。

UART6入口只检查接收标志、保留空分支并清溢出。当前UART6没有初始化；它是遗留接口。如果以后打开UART6接收中断，还必须实际读走接收数据，单清溢出不能消费接收寄存器。

### buttons_init、buttons_poll、buttons_get_last_action

`buttons_init()` 调 `key_init(10)`；库将C15/C14/C13/C12设成上拉输入。每10ms扫描：低电平累计按下时间，短按事件在松手时产生，长按阈值1000ms。当前消抖门槛10ms。

`buttons_poll()` 遍历四键，读取动作，RELEASE跳过，其他动作立即清掉并记入 `last_action[]`。KEY1写 `car_cmd=1`并直接调用发车；KEY2写0并直接调用停车；KEY3/4动作被消费但不执行车辆动作。短按与长按没有分成不同功能。两个键同轮循环都有效时，KEY2在KEY1之后处理。

`buttons_get_last_action()` 检查索引，读后清零，用于诊断；当前控制链未调用它。

库 `key_scanner()` 在下一次松手扫描时会把未消费短按重新写成RELEASE。即短按事件大约只有一个扫描周期可见。主循环视觉/打印用时超过10ms时，存在漏掉短按（包括STOP）的路径。长按则可能在每次扫描重复置位，不是单次边沿事件。应使事件保持到消费，尤其停车事件。

### vis_deal 的所有步骤，2034～2125行

1. 读取GPT1，记总耗时起点。
2. 函数内静态 `cached_th=-1`、`frame_since_otsu=0`。每次计数加1，第10帧重算Otsu，首次成功直接缓存，后续缓存=`0.3*新+0.7*旧`再转整数。前9帧默认阈值128。停止重发不会重置这两个函数内静态变量。
3. 遍历全部22560像素，灰度严格大于阈值才设白，否则黑。
4. 在连通滤波之前做 `out_of_bounds_check()`，保存原始图出界判定，避免底部黑行造成滤波连锁擦除后误判出界。
5. 连通滤波，保留底部连通白区。
6. 斑马线检测使用滤波后的图，但检测窗口来自上一帧边界，因为本帧边界还没搜。
7. 如果斑马线状态成立，只在false→true时报ZEBRA，保持帧也不报LOST；否则原始出界成立时报LOST。更新 `zebra_prev`。
8. 清左右边界为255、exist为0。此时中线与err仍是上一帧结果。
9. `sweep_boundaries()` 搜边界，函数返回值被忽略；搜线失败不直接变成LOST。
10. 只有 `cross_cand_present || oblique_valid` 时调用十字检测及补线。这个优化绕过了十字漏检退出状态机，见审查问题。
11. `pho_center()` 生中线、算偏差。
12. 置 `vis_frame_ready=1`，导出轨迹，写总耗时，返回事件。当前没有任何业务读取/清 `vis_frame_ready`；WiFi也按帧计数调用，不使用该标志。

## 4. Otsu、连通滤波与正常搜线

### compute_otsu，174行

每隔4行4列取一个灰度样本，当前30×47=1410个。256项直方图统计灰度。遍历候选阈值，计算背景/前景权重与均值，最大化类间方差 `wB*wF*(mB-mF)^2`。夹到20～235。

它只决定黑白分界，完全不识别赛道形状。全黑或单一灰度图仍可返回夹限阈值；后续图像有效性检查不能由Otsu成功替代。使用float适配M7浮点计算。

### filter_bottom_connected，1883行

底行所有白像素作为种子，不只选一个赛道区域。对118～10行逐行向上传播，0～9行不滤波。

每行复制上一行连通标记 `prev[]`，随后三趟：左→右使用下方连通±2列及本行左链标记；右→左补右链；最后统一把没连通的白像素擦黑。先标记后擦除让左右扩张对称。

这是逐行连通传播，不是完整通用二维洪泛。底行所有白区域均可保留；与底部连通的杂白仍可能进入后续计算。若底行全黑，底部110行的白区会全部被抹掉。

### longest_white_col，257行

在中间四分之一到四分之三列，每5列采样。逐列从底向上数连续白高度，第一处黑停止，取最长者为种子。相同长度保持先找到的列；全无连续白时默认94。

### sweep_boundaries，455～899行

先复位本帧候选及斜入状态，清raw数组。特别注意：每帧清 `oblique_real_side=0`，却故意保留 `cross_oblique_used`，这与跨帧漏检保持发生冲突。

底行从种子向左右找边界，遇连续两个黑像素停止；间距不足3返回失败。靠最左/右屏边视为伪边界。路宽夹20～160，写底行边界及raw真实标志。

逐行从118扫到5：

1. 左搜索起点为上一行左边界+8，右为上一行右边界−8；十字后强制从seed重搜。
2. 起点为白时向外找黑黑；起点为黑时退回seed重找；满足边缘范围且找到白才算真实边界。
3. 在任何外推/补线前保存raw列号与raw exist。
4. 从连续白区重新找到任意边界时，白区≥3行且远侧行≥31就提交十字候选，并强制seed模式。
5. 执行斜入单边丢线、下拐点、上拐点状态机，详见下一节。
6. 双边真实且左<右：更新路宽，恢复正常跟边起点。
7. 只有一边：用最近路宽外推另一边并夹图像范围，外推侧exist仍0。若在十字后seed模式则禁止外推、该行标空并继续。
8. 双边都丢或边界交错：检查中间采样列是否全黑。连续5行全黑就把更远行全部标空并返回1；这是局部搜线失败，不等于外层LOST事件。
9. 双丢但仍有白：按十字白区累计，连续3行且行号≥31可立即提交正入候选，扫得过远时取消。
10. 无有效边界行标空，下一行回seed；斜入上拐点搜索中则强制列168或20重扫。
11. 正常行写边界/真实标志，再更新下一行起点。0～4行正常扫描不填，后面中线可用白像素重心兜底。

路宽这里是图像像素宽，不是底盘轮距。它随透视和当前扫描行变化。

## 5. 十字：每个辅助函数与状态分支

当前 `CROSS_USE_OBLIQUE_SWEEP=1`，使用耦合扫线斜入检测；关闭该开关的旧算法保留在源码，但当前编译排除。

### 当前斜入辅助函数

- `cross_edge_l`、`cross_edge_r`（279/288）：读取本帧raw真实边界，缺失分别返回−12、200哨兵。读取raw避免尚未写g_vis的当前行被错当丢线。
- `cross_oblique_dn_at`（297）：先保护y−3、y+4范围。左墙要求当前及上方3行真实、下方相邻变化≤10、相对上方有向右撕裂；右墙镜像处理。输出下拐点行列。
- `cross_find_oblique_dn`（348）：从119向已扫当前行找下拐点。当前调用行最低5，不会扫到uint8下溢；若未来传0要重新检查循环。
- `cross_oblique_up_tear`（360）：用当前及下方3行判断上拐点撕裂方向。
- `cross_oblique_up_stable`（384）：上拐点候选上方再扫足3行，比较相邻边界差≤10。
- `cross_oblique_lost_side_continuous`（420）：上下拐点之间，对侧真实行不允许超过10，降低把普通单边弯道当十字的概率。

这些比较中部分邻行没有显式拒绝哨兵，“哨兵之间差为0”也可能满足稳定条件，应补齐有效性约束；当前主机复现集中验证下述跨帧越界，并未把所有斜入误检概率当成已测结论。

### 斜入状态机在sweep内部，593～751行

## 8. 控制层：每个状态、每个目标生成步骤

### 参数与状态变量

同步函数把前瞻参数搬到asc_far，把config.h的四轮PID参数搬入结构，统一OutMax/Min为±60。不存在已实现的在线菜单或参数接收器，“菜单直接绑定”的注释属于移植残留。

### control_state_launch

只允许IDLE或STOP进入，运行中再次START直接返回。清err_last、speed_filtered、堵转/停车计数/停车原因。清四个PID的Target/Actual/Out/OutCmd/历史误差，设限幅，加载增益，同步前瞻，复位视觉/里程。

- 当前ENCODER_ENABLE=0：`launch_openloop=0`，直接CAR_RUNNING。没有固定40%冲刺；下一帧视觉决定四轮目标。
- 恢复编码器：`launch_openloop=1`，CAR_LAUNCHING；5ms分支将四轮直接给40%。

允许从STOP直接再发车，但没有在重置多变量之前先统一关闭5ms消费端，也没有等待物理停稳；不能把“状态可发车”理解成“车辆已静止”。

### control_update 的四个分支

每次先从IMU取最新滤波值放 `gyro_z_dbg`。

IDLE：四轮Target清0，三个运动dbg清0。真正关电机由输出使能/stop完成。

LAUNCHING：代码只取左前与右后的**平均线速度**，变量却命名rpm。注释“两轮以上达标”不准确；一个轮速很高也可能把平均值拉过180cm/s。达到180或5ms计数达200（1秒）就切运行，给60tick过渡保护，并把speed_filtered放在至少180附近；否则dbg前进目标180。

切换这一帧不执行RUNNING块、不写四轮Target。Target发车时清过0，因此下一个5ms中断会按目标0与实际约180～200计算，复现出首拍−8%输出。开环期间PID的Out也没有跟随40%进行预置，过渡限幅只能限制幅度，不能保证无冲击切换。

RUNNING严格顺序：算omega→规划/平滑vx→算vy→逆解四轮→逐个写Target→更新dbg。STOP调control_stop_poll。default无动作，没有非法状态兜底关PWM。

### omega_calc 的逐项含义

```c
e = err;
if (e < 2 && e > -2) e = 0;
delta = e - err_last;
err_last = e;
omega = -1 * (0.60*e + 0.004*e*fabs(e) + 0.30*delta)
        - 0.08*gyro_z_dbg;
```

实际代码用条件表达式求绝对值，并非调用fabs。最后夹±120。

- 小偏差严格位于(−2,2)才归零，±2本身不归零。
- 线性项偏差越大转向越大。
- 二次项大偏差增长更快。
- D是相邻处理帧差，没有除真实dt；帧间隔变化会改变有效响应，不能直接当标准连续时间微分系数。
- 正常朝前且未镜像图像，err>0需要右转，所以视觉项整体负号。
- gyro_z>0代表已经左转，减去正阻尼抵消它；右转负读数会产生左向阻尼，抑制甩尾。
- 这是视觉PD/非线性P加实际旋转阻尼，没有独立计算 `omega_target-gyro_z` 的角速度PID，也没有角度积分、航向角闭环。
- 死区只用于转向；速度规划和横移仍读原始g_vis.err。

### speed_plan 与前进指令平滑

| 原始绝对偏差 | 未平滑前进目标 |

| 4～50px | `120+(abs(err)-4)/46*(80-120)` |

### control_state_stop、control_stop_poll

请求停车：IDLE直接返回；否则记录原因，设STOP，停车计数0，退出起步开环，暂关速度环并置StopBrake。

当前无编码器请求函数立即motor_stop；poll又清输出使能、制动标志、所有Target/Out/OutCmd、omega/vx/vy dbg，开启IMU零偏跟踪并回IDLE。这个IDLE是软件结束停车动作，并没有速度反馈证明实车停稳。仍在滑行/转动时开启偏置跟踪，会把部分真实转动纳入零偏。

恢复编码器poll按视觉帧执行：停车计数加1，四轮Target0，读取四轮实际速度绝对最大值，开PID并置StopBrake。四轮都<5cm/s或30帧超时则关PWM、清目标/输出、回IDLE、开偏置跟踪。

StopBrake在PID里禁止正向PWM，因此只适合此前所有轮都向前转的制动假设。麦轮横移/原地转向可有倒转轮；倒转轮需要正向力矩制动，而这里被夹成0。当前输出关闭与机械驱动器PWM=0的具体滑停/短路制动状态还需以DRV8701E实际接口电路为准，不能把motor_stop注释的“断电”当作已验证的电气模式。

恢复编码器后STOP的poll依赖图像。缺帧时Speed_PID_Enable=0能在5ms分支关输出，但停车状态、超时和回IDLE不会推进。

### control_stall_watchdog

当前直接清计数返回0。恢复后仅RUNNING且前进目标≥120才检查；四轮绝对速度都<25，连续15个处理帧则请求STOP_REASON_STALL。任何一轮≥25就清计数，不检测单轮故障，也不覆盖主要横移/自转任务。

当前直道最大指令就是120，弯道80～120。经过一次降速后再缓升至120，float递推可停在119.9999237，永远不满足≥120。实际源码主机执行1000帧、四轮实际0，仍原因0未停。应该在可行运行速度范围判断，或使用每轮目标/实际与持续时间，而不是把检测门槛放在指令上限。

```c
vy *= MECANUM_Y_SIGN;                  // 当前+1
rot *= MECANUM_W_SIGN;                 // 当前+1
out[FL] = vx - vy - rot;
out[FR] = vx + vy + rot;
out[RL] = vx + vy - rot;
out[RR] = vx - vy + rot;
```

half_diag变量名容易误解，它是半轴距+半轮距的等效系数，不是欧氏半对角线。L/W是配置默认值，尚需实车测量。轮径和减速比没有出现在这个线速度形式的逆解中；轮速测量用每米计数独立标定。

适用于当前约定的45°辊子麦轮布局。它是理想运动约束换算，输出为轮速目标，不保证实车无滑移，也不保证实际车身omega等于输入。

纯前进四轮同号；纯左移FL/RR负、FR/RL正；纯左转左侧负、右侧正。vy=0时前后同侧目标相等。代码没有对四轮最大目标做统一比例缩放；单独PWM饱和会破坏合成的目标比例。

`mecanum_drive`是逆解(vx,0,0)封装，`mecanum_spin`是(0,0,omega)封装，当前RUNNING直接调用inverse。`motor_get_wheelbase_mm`、`motor_get_track_mm`、`motor_get_wheel_dia_mm`分别返回轴距、轮距、轮径宏，用于启动打印，不会重新测量底盘。

### motor_set_wheel

检查上界索引，把整数占空比转int32，应用该轮方向补偿，夹±60。非负写DIR高、PWM为d×100；负值写DIR低、PWM为−d×100。库PWM_DUTY_MAX=10000，因此百分数10转底层1000。

这里输入已经是整数，当前0.1%或0.01%的纠偏会被前一层转int16丢掉；VOFA OutCmd还能显示小数，可能与实际下发有差别。

四个DIR_INVERT当前全0，是否与实物前进方向一致未硬件验证。电机电气方向补偿、编码器计数符号、视觉转向符号、IMU安装符号与麦轮Y/W符号各有职责，不能随意改单轮补偿来修复整车坐标方向。

### motor_set_wheels、motor_stop

顺序调用四次单轮设置，没有四路原子同步提交。stop调用四轮0，因此DIR实际会统一写高，未“保持原DIR”，motor.h注释不准确；PWM都0。17kHz是载波，5ms是指令调节周期，二者不是同一个频率。

## 11. 四轮速度PID与临时开环：pid.c

源码：[pid.h](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/code/pid/pid.h:19)、[pid.c](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/code/pid/pid.c:30)。

### PID_INC_t 与 PID_INC_Init

每轮一份Target/Actual(cm/s)、Out(累加反馈占空比)、OutCmd(最终占空比)、Kp/Ki/Kd/Kff、Error0/1/2、OutMax/Min、OutDeltaMax。

Init空指针返回，清目标/实际/输出/历史误差，OutDeltaMax=0表示不限制。它不清增益和限幅，调用方另设。`Speed_PID_Init`循环初始化四轮、设置±60、载入参数、关总使能。

### Speed_PID_Sync_Params

左前/左后Kp=1，右前/右后Kp=1.2；四轮Ki=0.025、Kd=0.10、Kff=0.10。这是编译宏复制，没有读取菜单改过的变量；运行中调用会重新覆盖为config默认。

### PID_INC_Update 的完整步骤

1. 空指针返回。
2. `e0=Target-Actual`。
3. `delta=Kp*(e0-e1)+Ki*e0+Kd*(e0-2*e1+e2)`。
4. 若起步过渡计数>0，delta夹±8。
5. 若该轮OutDeltaMax>0，再夹该值；当前初始0，保护不启用。
6. `Out=clamp(旧Out+delta,OutMin,OutMax)`。
7. Target>Actual时 `OutCmd=Out+Kff*(Target-Actual)`，否则OutCmd=Out。
8. OutCmd再次夹到全局±60。
9. StopBrake时正OutCmd清0。
10. Error2←Error1，Error1←Error0，留给下一拍。

这是离散增量PID，采样时间已隐含在参数里，没有显式dt。改变5ms需要重新考虑Ki/Kd及滤波。它有输出夹限，没有单独积分状态；不能把它说成已完成完善的饱和反馈/积分反算。

名为“前馈”的第7步乘的是速度误差，而且只在误差>0时加，因此是单侧误差增强，不是常见的 `Kff*Target` 目标前馈。反向目标时它并不对称。四轮轮速闭环也不是独立车身角速度闭环。

### Speed_PID_Crtl：编码器恢复分支

先更新四轮Actual，过渡tick减1。launch_openloop=1时：tick+1，四轮固定40%，直接return，不看Target、不算PID。然后检查Speed_PID_Enable，关闭则motor_stop；开启则逐轮PID并把OutCmd转int16交motor_set_wheel。

开环条件在总使能之前。状态切换必须正确清launch_openloop，否则总使能关闭并不能单独覆盖起步开环输出。60tick先减再判，使过渡保护实际受执行顺序影响，不应机械宣称每一拍都完整保护300ms。

开环时OutCmd未跟实际40%同步，VOFA可能显示0而电机在40%；PID关闭路径motor_stop也没立即更新所有OutCmd。这是诊断值与最终硬件命令可能不一致的另一处。

### Speed_PID_Crtl：当前无编码器分支

```c
cmd = 0;
if (Speed_PID_Enable && !Speed_PID_StopBrake) {
    cmd = Target * 0.10f;
    cmd = clamp(cmd,-20,20);
}
Actual = 0; Out = 0; OutCmd = cmd;
motor_set_wheel(i,(int16)cmd);
```

四轮均执行，没有积分、没有PID_UPDATE。Actual=0表示无反馈，不代表实车静止。速度目标100映射10%，不代表10%能让车轮正好100cm/s。电池、摩擦、驱动死区都影响实速。

即使目标每20ms不变，中断也每5ms检查使能并更新输出。PWM整数化可能把微小差速吞掉，限幅也可能改变四轮比例；这条临时模式用于方向与视觉链路验证，不能拿实际0曲线评价PID性能。

## 12. IMU：初始化、零偏、滤波、反馈

源码：[imu.c](/C:/Users/Lenovo/Desktop/麦轮资料/McarPVC/code/imu/imu.c:16)。SPI4引脚C23/C22/C21/C20来自库。量程±2000°/s，换算因子16.4LSB/(°/s)。

`imu_init()` 失败最多重试11次，之间100ms；成功 `imu_calibrate_gyro(200)`。校准200次，每次get_gyro、累加raw Z、等5ms，总约1秒，平均作bias并清滤波角速度。samples=0直接返回；没有方差检查。

`imu_update()` 每5ms读陀螺XYZ，但控制只用Z。先减bias再除16.4；若bias_tracking=1，则以 `0.005/(0.8+0.005)≈0.00621` 缓慢追踪raw零偏；乘安装符号；输出 `gyro_z_dps += 0.5*(dps-gyro_z_dps)`。本次输出先用旧bias计算，下一次才体现本次bias更新。

`imu_get_gyro_z_dps()` 返回缓存滤波读数，不会再次访问SPI。`imu_get_gyro_raw_x`、`imu_get_gyro_raw_y`、`imu_get_gyro_raw_z`返回库最新原始值。`imu_get_acc_raw_z`返回加速度缓存，但本控制链没有调用get_acc，不能把该接口读数理解成已持续更新的姿态数据。

`imu_set_bias_tracking`规范化开关。行驶关、IDLE开；没有独立静止判断。源码注释“用于停车静止检测/自转闭环”不等于当前实现：停车判据来自编码器或无反馈直接结束；IMU只用于转向阻尼，没有航向积分。

## 17. 对照之前双电机加舵机的项目

之前转向控制的最终执行器是舵机角度；驱动电机主要负责前进。当前视觉像素偏差仍是同类输入，但转向输出变成车身角速度指令，通过四轮速度差执行。

视觉仍须保证“看到了什么、偏差是否可信”，速度规划仍负责偏差大时减速。新增的麦轮分配连接整车三自由度指令与四轮轮速，四个轮速PID各自只解决本轮目标跟踪。轮速闭环稳定不能修复视觉误检、补线内存错误、坐标符号错误，也不能自动保证车身无滑移。

当前整车还保留摄像头反馈的循迹外环和IMU阻尼，但轮速内环临时开环。应分别观察视觉误差、车身转动和每轮实际速度；“PID”这个函数名不足以判断当前到底运行了哪一种反馈控制。
