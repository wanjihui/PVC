# 国庆总结

完成小车组装，逐一验证电机及驱动、WiFiSPI、IMU、摄像头和四路编码器，修正电机方向、编码器方向及车轮对应关系，确定车体尺寸、轮周长和电机起转占空比。编码器四倍频测试出现异常后，回退到一倍频并恢复正常采样。

完成初版控制代码，将轮速统一为 cm/s，建立“图像处理—整车运动指令—麦轮运动学分配—四轮独立速度环—电机输出”的控制链条。基于队友的上位机增加调试日志、摄像头画面和姿态显示，实现无线查看图像与运行数据。

# 10.8—10.9

先调四轮同速直行，再恢复视觉循迹，通过赛道试跑和保存的数据迭代速度环、视觉转向及陀螺反馈，增加 0.5 秒起步加速和上位机实时调参。根据 IMU 倒装实测情况，修正控制所用 Z 轴角速度符号。

控制思路发生变化：最初只使用前进和自转，沿用舵机车的循迹思路，不加横移。试跑中发现出弯漂移、残余转动和回正慢的问题，单靠转向难以改善，因此加入少量横移辅助，让前进、转向和横移共同参与循迹，并保留陀螺反馈与四轮速度闭环。

# 10.11

优化上位机摄像头显示，增加贯穿画面的取值区域绿线、同色左右边界和特殊颜色拐点标记，隐藏上下各 20 行的处理线条，支持图像等比例填充显示区域。

优化 WiFi 异步发送调度，提高图像上传帧率目标，减少通信对主循环的阻塞；速度环和 IMU 仍保持 5 ms 节拍。针对麦轮过弯打滑，提出入弯降速、出弯稳定后加速的方案。

# 10.12

继续分析图像、参数同时断流的问题，补充上位机接收统计与接收确认，增加车端异步重建连接、停车后重新入网的恢复流程，恢复效果继续通过实车采集验证。

对照暑假集训项目的视觉算法，修正十字上下拐点补线、短时漏检保持和斜入十字侧别判断；修正普通弯道缺边被误当补线、影响中线取值的问题。

让上位机取值绿线随在线前瞻调整更新。根据轮速数据小幅提高左前、右后速度环比例参数，并保留实跑分析和参数迭代记录。

# 10.13

参考 HDU 项目固定连接的思路，将参数、文字日志和摄像头图像统一到一个 UDP 端口，用包类型区分，保留旧三端口兼容方式，减少正常上传期间反复重建连接。

启用弯道减速：默认直道 150、普通弯 120、紧弯 100 cm/s，连续图像确认入弯，出弯时结合视觉偏差和实际转速稳定判断恢复速度，保留起步斜坡、横移辅助和四轮速度闭环。

对比前瞻 45、55、60 的赛道表现，将默认前瞻改为 60。分析发现，即使直道速度设为 200，车仍大部分时间保持紧弯限速，因此增加弯速、进入/退出条件和加减速率的实时调参。

上位机默认使用完整视觉循迹字段，避免只保存姿态角；加入弯道参数后，按需求移除四轮速度环的调参控件，保留 23 项循迹、起步和弯道参数，并更新桌面 EXE。

继续分析单边中线异常及出弯斜行：发现跨行共用的参考路宽可能影响单边外推；当前单一前瞻偏差难以分别反映横向位置与车头方向，陀螺阻尼也不能独立恢复航向。下一步准备修订可信路宽，并探索位置与航向分开控制、出弯横移辅助；这些控制改法尚未实施或完成实车验证。
