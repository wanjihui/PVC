# 本轮视觉修复、暑假算法差异与IMU纠偏方案

本轮依据2026-10-14 21:41保存的CSV与三张截图修改。实现只涉及视觉、停车弯级观察及其应用调用；没有修改速度、前瞻60、视觉增益、gyro_kd、横移增益或四轮PID。IMU航向/角速度闭环部分仅为方案，尚未加入代码。

## 1. 两个画面问题的原因与修复

### 蓝色边界消失、移动后又出现

旧 `sweep_boundaries()` 的左右搜索起点分别是 `prev_l+8` / `prev_r-8`。起点为黑时直接退到固定seed；seed也黑时不主动寻找旁边的白段。改变车位可能使某个起点重新变白，边界因此重新出现。本轮新增 `sweep_recover_edge()`：先局部搜跳变，再扩大3倍，最后全行恢复离预测墙最近的真实跳变。局部半径采用summer稳定版 `last_valid_width/4`，限制3..25。稳定版左墙用黑白白，当前为延续抗单像素噪声约束采用黑黑白白；右侧对称白白黑黑。因此属于参考其机制适配，不是宣称逐字移植。底行seed不白时用稳定版最长白段恢复。

另有独立故障：普通单边弯道可能触发宽松下拐点判据，之后没有找到上拐点，旧代码却在y=5制造(187,0)/(0,0)，同时清空真实墙。真正的上拐点候选尚未跨帧确认时，也会先擦墙。未确认的正入候选恢复单边时同样有清空分支。上位机收到边界255不画蓝线，`pho_center()`仍用白重心画黄线，因此“蓝线没了但黄线存在”并不矛盾。

现在扫描只收集候选，不擦掉已有真实墙；确认后由 `cross_repair()` 改写补线。没有真实上拐点则取消本帧斜入候选，不虚构顶角。已有确认/4帧保持继续有效。代价：上拐点完全不在视野时，不再单凭下拐点强行宣布斜入；此时保留真实单边循迹。

### 黄线靠真实边界过近

旧逐行缓存修订仍有缺口：没有真实双边时可能继承默认60或最近某个远行20px宽度；K1还会将近端参考复位。当前第y行单边不能保证此前其他行的路宽适合它。

现在 `learned_row_width[y]` 只保存同一图像行实际双墙测得的20..160px宽度，避开十字候选和斜入搜索状态；冷启动清空，停车/K1保留。单边对应白段连续延伸到画面边缘时，可见长度是路宽下界，例如左墙70、白区直到187，完整路宽不可能只有20。该下界只用于外推，不伪装成完整路宽标定。

按照用户新增要求，`vision_white_center(y,&c_white)` 用滤波后二值图本行全部白点求重心，至少3点有效：

```c
// c_width保留未裁剪值，仍可以小于0或大于187
// 左单边：离左墙更远是更靠右
c = max(left + width/2, c_white);
// 右单边：离右墙更远是更靠左
c = min(right - width/2, c_white);
```

没有足够白点仅用宽度外推；双边仍中点，双缺仍白重心。不是对两边都取数值较大的点。最后再执行原有贴边截断、近端5行趋势和前瞻缺行err外推。白重心属于可见白区，不保证是画面外完整道路的真实中心，连通滤波剩下的多块白区仍可能影响它。

## 2. 停车显示直/小/紧弯

当前WiFi参数/IMU、摄像头早已不受K1/K2控制。问题来自停车时 `curve_reset()` 清规划弯级，`control_update()`直接返回，所以旧getter一直返回0。

现在 `app_vision_poll()` 每张新图像执行 `control_observe_vision()`，位置在drive_allowed检查之前。它使用独立的上一帧误差计算视觉P/二次P/D需求，用现有70/140°/s阈值和两张连续同类新帧确认预览弯级，不写PWM、轮目标、转向D缓存或运行规划状态。

`control_curve_level()`：停车返回这个视觉预览；运行返回实际规划确认/保持弯级，继续受出弯稳定释放控制。两者都为0/1/2，沿用DATA偏移148的uint32，不改桌面EXE/MCAM/UDP格式。它按转向需求分级，不等同于独立测得的道路几何曲率；预览停车时能降级，运行规划仍可为避免弯中加速而保持紧弯。

## 4. IMU：当前阻尼与下一步纠偏（仅方案）

实际代码 `control_tick_isr()` 每5ms：

```c
gyro_z_dbg = imu_get_gyro_z_dps(); // 已用IMU_MOUNT_YAW_SIGN=-1归一化：左转正
omega_dbg = vision_omega_command - ctl_gyro_kd * gyro_z_dbg;
// 随后限±ctl_omega_max -> mecanum_inverse(vx,vy,omega) -> 四轮速度目标 -> PID -> PWM
```

gyro_kd=0.30时，视觉指令0、实测左转+100°/s，输出转向指令−30°/s；车还在转就给反向轮速差，转速消退则这项减小。这是角速度负反馈阻尼，不是目标角速度误差PI，也不测车头相对赛道的方向。视觉D项是像素err的逐帧差分，两者不同。

车头已经偏了15°但不再转时，gyro=0，阻尼为0，不能自动恢复15°。当前IMU也参与出弯恢复的低转速判据，姿态供上位机显示，但没有yaw目标误差控制。若粗略假设轮速分配能使实际转速r≈omega_dbg，则稳态r≈omega_vis/(1+gyro_kd)；继续单纯增大阻尼也会削弱持续转弯能力。此式是理想化解释，不是当前轮胎打滑情况下的实车模型。

建议分两步：

1. **角速度跟踪环**：视觉先给 `omega_ref`，5ms计算 `e_r=omega_ref-r`，初期用 `omega_mix=omega_ref+Kpr*e_r`，必要时再加有抗饱和的积分；随后仍运动学→四轮速度PID。不能把新环输出直接当PWM，也不要把新PI和旧大阻尼无计划叠加。该环解决“想转多少、实际转多少”，仍不独立解决静止斜行。
2. **位置与航向分开**：近场中线位置用于横移，近远中线趋势用于车头相对赛道方向；真实连续边界优先，十字/估计点降低可信度。像素斜率不能未经相机地面标定就当真实航向角。视觉可靠时更新路向参考，IMU在图像之间积分短时相对航向；方向误差生成omega_ref，角速度环跟踪它。直道参考不是上电yaw永久锁死，也不能把出弯时已经斜着的车头直接认作正确参考。

ICM20602为六轴，重力可以约束俯仰/横滚，不能单靠加速度计观测绕重力轴的绝对航向，长期yaw会受陀螺零偏影响。见[NXP AN3461](https://www.nxp.com/docs/en/application-note/AN3461.pdf)。因此IMU适合高频角速度和短时航向，赛道视觉提供长期道路方向；倒装须统一车体坐标，不可直接拿当前原始姿态yaw给目标闭环。仅凭gyro也不能辨别横向平移打滑，不能用IMU替代位置视觉。

执行顺序：本轮视觉稳定后，先记录omega_ref、实测归一化r和差值，低速调角速度P；再验证直道近/远中线能区分“车身偏移但平行”和“车头倾斜”，最后加航向外环、横移位置环。停止/丢线仍优先，积分停车清零、饱和时限积，视觉过期不持续累积纠偏。
