## 当前入口

`code/config/config.h` 中 `MOTOR_DUTY_TEST_ENABLE=1`。测试初始化只执行时钟、UART1、电机、编码器和按键；PIT_CH0每5ms只采编码器，PIT_CH1每10ms只扫描按键，不调用PID。IMU、摄像头、WiFi均不初始化/调度。

上电四轮PWM=0；K1允许输出，K2全部清零，同一次循环同时看到K1/K2时停车优先。主循环每次分别写四轮，独立值在 `project/user/src/main.c` 顶部：

```c
volatile int16 motor_test_duty_fl = 7;  // 左前M1
volatile int16 motor_test_duty_fr = 0;  // 右前M2
volatile int16 motor_test_duty_rl = 0;  // 左后M3
volatile int16 motor_test_duty_rr = 0;  // 右后M4
```

每个值是整数百分比，正值向前、负值向后、0停止；测试限幅为±20%。默认只测左前7%。保持实物已验证的电机方向补偿0/1/0/0，编码器方向补偿暂保留0/1/1/0，但切四倍频后应复核前进计数为正。

主循环中的四个调用：

```c
motor_set_wheel(WHEEL_FL, fl);
motor_set_wheel(WHEEL_FR, fr);
motor_set_wheel(WHEEL_RL, rl);
motor_set_wheel(WHEEL_RR, rr);
```

UART1 B12/B13、115200，连续FireWater八通道，约每20次主循环发一次：FL/FR/RL/RR实际命令占空比(%)，FL/FR/RL/RR轮速(cm/s)。没有混入周期性文字。这个测试入口没有WiFi上传；上位机UDP无新数据属于预期。PWM仍为17kHz，四路引脚未改。

## 测量步骤

1. 初次架空车轮，一次只给一个轮子非零值，其余为0；记录电池电压及架空/载荷条件。
2. 修改对应值，编译下载；上电等待，按K1开始观察。
3. 从较小占空比逐步增加，每次用K2停稳，再尝试从静止启动；不要把已转起来后还能维持的占空比当作起转阈值。
4. 例如7%不转、8%可靠起转，则记8%，真实阈值在(7%,8%]之间。先按1个百分点精度即可。不能填7.5到当前int16接口，它会丢弃小数。
5. 同一值重复从静止启动3～5次。四轮分别记录正向，必要时用负值测反向；架空起转与正常载荷起转分别记录。

测试的是起转占空比，不是把电源电压改成7V或8V。占空比阈值会随供电和载荷改变，电池电压必须一起记录。正反向阈值和维持转动阈值先记录，不直接自动写入PID补偿。

## 尺寸、传动和计数

用户提供L=20cm、W=18cm、车轮周长=19.5cm，代码几何中心距宏分别存200mm、180mm；周长用cm，等效直径由周长推算约62.07043mm，不能把它标成卡尺实测值。外部电机齿轮传动68/16=4.25，不代表已经查清电机内部减速比。

1024线编码器；按68齿轮与车轮同轴、直接啮合30齿编码器齿轮计算。编码器轴与车轮转数比68/30；16齿主动轮不再重复乘进车轮到编码器的换算。

驱动的 `encoder_quad_init()` 改为 `kQTMR_QuadCountMode`，对A/B状态变化做硬件四倍频计数；独立 `encoder_dir_init()` 仍保留原脉冲+方向的一倍频语义。SDK与其他样例未修改。

```text
编码器每圈计数 = 1024 × 4 = 4096
车轮每圈计数 = 4096 × 68/30 ≈ 9284.26667
每厘米计数 = 4096 × 68/30 ÷ 19.5 ≈ 476.11624 count/cm
10个车轮圈累计计数变化 ≈ 92843（起止相位可能造成约1个计数差异）
轮速(cm/s) = 5ms计数增量 / (0.005 × 每厘米计数)
```

这些是规格和传动计算结果，不冒充实测计数；四轮应复核方向和圈数。原始增量、累计计数与UDP累计计数字段仍为整数count；速度为cm/s，距离为cm。计数没有物理长度单位，不能把原始count字段直接改成cm且维持原协议不变。

`encoder_set_counts_per_cm()` / `encoder_get_counts_per_cm()` 替代旧每米接口，四轮共享值。初始化/标定值变化时预计算速度系数，每次换算只乘法。标定用累计计数差除以独立测量的距离(cm)，不相加低频读取的瞬时增量。改变解码方式必须同步改变换算系数。
