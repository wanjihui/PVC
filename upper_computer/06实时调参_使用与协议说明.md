# 06 实时调参

本页使用车端新增的 MCAR 参数命令。原始参数包 8081、文字日志 8082、图像 8083 保持兼容；01～05 页、飞机模型、摄像头叠加图和快捷命令均保留。

## 使用方法

1. 下载本次配套 McarPVC 固件。旧固件没有参数命令解析器，等待超时是正常结果，不能视为已修改。
2. 启动新版上位机，01 页开始监听。01 的发送目标为 WiFi 模块 IP，命令端口默认 **6666**。收到第一份有效参数或启动日志时会识别模块 IP；随后保留用户编辑，不跟随其他发送方切换。
3. 打开 06，点“读取车辆全部参数”。车辆返回全部 23 项和 DONE 后，确认栏才作为一次完整读取提交。读取不会改变车辆参数、不会发车。
4. 在编辑栏修改一个值，点对应“应用此项”。范围和有限数校验通过才发送。车辆确认后显示“已应用（车辆确认）”；拒绝、超时或旧回包都不会显示成功。按键 K1 发车、K2 停车仍按原固件处理，本页没有启动命令。
5. 在停车状态调整起步时间；车辆运行时对此参数返回拒绝。其它参数实时调整，建议每次只改一项并保留对应 CSV、图像和方案。
6. 本地默认、填入确认值、保存/导入/导出 JSON 都只改变电脑编辑值或文件。**不会自动应用到车辆。** 车端参数不写 Flash，复位恢复 config 默认值；保存的电脑方案可再次导入、逐项应用。

**`cruise_cms=0` 只将前进速度 vx 置零，视觉转向 omega 和横移输出仍可能存在，所以 0 不等于停车。需要停车时请按 K2。**

## 参数

| 键名 | 默认 | 范围 | 调整作用 |
| --- | ---: | --- | --- |
| cruise_cms | 150 | 0～200 cm/s | 同时改变直弯目标速度；降速给纠偏更多时间；0 不等于停车，停车按 K2 |
| ramp_ms | 500 | 100～2000 ms，5 ms 整数倍 | 增大起步更缓；仅停车可改 |
| preview_row | 55 | 20～100 整数 | 图像行号减小看得更远；增大更靠近车头 |
| deadband_px | 2 | 0～10 px | 减小能纠正小偏差，也更容易跟随噪声 |
| omega_kp1 | 1.6 | 0～3 | 提高当前偏差的转向指令；过大会摇摆 |
| omega_kp2 | 0.012 | 0～0.03 | 提高大偏差下的转向；全部非零偏差都参与 |
| omega_kd | 0.3 | 0～2 | 响应相邻图像偏差变化；过大放大边界跳变 |
| omega_max_dps | 240 | 30～360 °/s | 放宽转向限幅；未到限幅时提高它不会增强指令 |
| gyro_kd | 0.08 | 0～1 | 抑制实际旋转，增大也会减弱转向 |
| lateral_gain | 0 | 0～1 | 将偏差分配到横移；优先保持 0 独立调好转向 |
| kp_FL/FR/RL/RR | 0.10 | 0～0.5 | 各轮速度误差的即时补偿 |
| ki_FL/FR/RL/RR | 0.001 | 0～0.01 | 各轮持续速度误差的积累补偿 |
| kd_FL/FR/RL/RR | 0 | 0～0.1 | 各轮速度误差变化的补偿，容易放大计数噪声 |
| ff | 0 | 0～0.1 | 正误差附加增益：仅 Target>Actual 时增加 ff×(Target−Actual) 输出，先保持 0 |

增益范围是程序边界，范围内的每个数值并不代表都适合实车。视觉输出的符号、陀螺安装方向、麦轮滚子方向、轮径和轴距不在本页修改。

`ff` 保留车端历史键名，但当前 `pid.c` 的计算是正误差的附加补偿：`OutCmd=Out+ff*(Target-Actual)`，条件为 `Target>Actual`，否则 `OutCmd=Out`。它不按目标速度直接给基础占空比；增加它会加强这一方向的欠速补偿，默认 0，不能把它当作测得的电机静态速度前馈系数。

## 线协议和确认

命令是 ASCII，以 LF 结束，一个命令一个 UDP 数据报。目标是 **模块的命令端口**，不是电脑的 8081/8082/8083。

```text
MCAR GET 123 ALL\n
MCAR SET 124 omega_kp1 1.7\n
```

车端从文字日志链路返回，可与普通日志同包、分包：

```text
[PARAM] 123 OK cruise_cms 150\r\n
... 共 23 项 ...
[PARAM] 123 DONE\r\n
[PARAM] 124 OK omega_kp1 1.7\r\n
[PARAM] 125 ERR STOP_FIRST\r\n
```

请求编号为 0～2147483647，程序随机选择起始编号然后递增。上位机核对请求编号、来源 IP、参数名、有限数和请求值；SET 回执值允许正常浮点打印精度误差。错误来源、未知编号、已结束请求、被新编辑替代的旧请求和早于当前请求的数据均不能确认新参数。

车端使用 float32 并以 `%.9g` 回报，例如合法上限 `0.1f` 会显示为 `0.100000001`。回执校验允许这一级浮点舍入并归到边界值；编辑栏输入仍严格执行表中范围，不能通过这一兼容处理发送越界参数。

1 秒无结果后使用同编号重试，最多总共发送 3 次。超过期限标记“未确认”，不能判断是命令丢失、已执行而回执丢失、旧固件，还是日志监听未启动；下一步应重新读取。GET 中某项缺失，即使收到 DONE，也不会误认为已读取完整参数。

读全部期间暂停其它参数请求，避免交叉读取与修改造成难以判断的快照。车辆启动标记 `MCAR_APP built ...`、已识别的数据连接超过 3 秒无消息、停止监听或切换目标 IP 时，已确认值失效，等待重新读取。

## 代码与验证

- `live_tuning.py`：参数清单、范围校验、请求重试和回包匹配、方案文件。
- `app.py`：06 页、逐项按钮、沿用模块地址、解码日志时提交 PARAM、断线状态。
- `tests/test_live_tuning.py`：非法数值、旧/错来源回包、GET 不完整、拒绝、重启、超时、本地文件、真实 UDP 回环。
- `tools/check_live_tuning.py`：原生 DearPyGui 按钮回调加真实本机 UDP 回环；检查确认前后值、拒绝越界发送、导入不发送、六页和原飞机模型。

本次验证覆盖软件协议与桌面界面，**没有接触实车或确认无线调参在赛道的实际效果**。报告的 `car_contacted=false` 用于明确这一边界。软件测试发送到 127.0.0.1 的独立随机端口，不使用车端地址或正在运行的上位机监听端口。
