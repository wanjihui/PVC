# PVC · RT1064 四电机麦轮循迹小车

McarPVC 是基于 NXP i.MX RT1064 的四电机麦克纳姆轮循迹工程，使用总钻风 MT9V03X 摄像头获取赛道图像，通过麦轮运动学分配四个车轮的运动指令，并使用 ICM20602 陀螺仪提供转向阻尼反馈。

底层基于逐飞科技 RT1064 开源库，视觉算法移植自个人先前的 `summer-smartcar` 双电机加舵机项目。当前阶段重点是四轮方向、视觉纠偏和串口调试。

## 当前版本

编码器尚未接入，WiFi SPI 暂时关闭；相关源码保留，通过 `code/config/config.h` 中的开关选择功能。

| 配置 | 默认值 | 当前行为 |
|---|---|---|
| `ENCODER_ENABLE` | `0` | 不初始化和采样编码器，不执行轮速 PID，也不依据轮速判断堵转 |
| `WIFI_SPI_ENABLE` | `0` | 不初始化 WiFi SPI，不上传无线图像和曲线 |
| `MOTOR_OPEN_LOOP_GAIN` | `0.10f` | 四轮速度指令乘以该系数，映射为 PWM 占空比 |
| `MOTOR_OPEN_LOOP_MAX` | `20` | 临时开环输出限制在 ±20% |
| `SERVO_ENABLE` | `0` | 麦轮底盘通过四轮配速转向，不使用舵机 |
| `VOFA_SEND_DIV` | `2` | 每两帧发送一次遥测，摄像头约 50 Hz 时上行约 25 Hz |

当前配置中的 cm/s、deg/s 表示规划指令，尚不能保证等于车辆实际运动速度。停车操作会立即撤掉 PWM，车辆随后机械滑停。

## 硬件与接口

| 硬件 | 用途 |
|---|---|
| RT1064 主板 | 主控，程序初始化为 600 MHz |
| 总钻风 MT9V03X | CSI 并口摄像头，188 × 120 灰度图像 |
| 两块双路 DRV8701E | 四路有刷电机 DIR + PWM 控制，PWM 频率 17 kHz |
| ICM20602 | SPI4 六轴 IMU，当前控制主要使用 Z 轴角速度 |
| 四路正交编码器 | 预留轮速反馈，当前默认禁用 |
| USB 转 TTL 串口模块 | 接收 printf 遥测，连接电脑上的 VOFA+ |
| 四个按键 | 当前使用 KEY_1 发车、KEY_2 停车 |

四轮编号和接口如下，轮子顺序在控制、运动学和遥测中保持一致：

```text
           车头
    M1 左前     M2 右前
    M3 左后     M4 右后
```

| 车轮 | DIR | PWM |
|---|---|---|
| M1 / FL 左前 | C9 | C8 |
| M2 / FR 右前 | C7 | C6 |
| M3 / RL 左后 | D2 | D3 |
| M4 / RR 右后 | C10 | C11 |

ICM20602 使用 SCK=C23、MOSI=C22、MISO=C21、CS=C20；该接口由库中的 `zf_device_icm20602.h` 定义。电机和编码器的方向、底盘尺寸及控制参数在 `code/config/config.h` 中配置。

## 编译与下载

1. 使用 Keil MDK 5 打开 `project/mdk/rt1064.uvprojx`。
2. 选择工程目标 `nor_sdram_zf_dtcm`，使用 ARM Compiler 6。本机已使用 ARMCLANG V6.24 完成编译；工程引用的设备包为 `NXP.MIMXRT1064_DFP.15.0.0`。
3. 确认设备为 `MIMXRT1064DVL6A`，执行 Build；工程已包含 SDK、逐飞库、业务源码和分散加载文件。
4. 在 Debug / Utilities 中选择与 RT1064 匹配的 ARM CMSIS-DAP 或 J-Link，确认调试连接和 Flash 下载配置后烧录。

`libraries` 中的 `.a`、`.lib` 文件属于工程依赖，需要保留。`Objects`、`Listings` 等编译结果不纳入版本管理，编译时会重新生成。

## 控制流程

```text
摄像头灰度图像
    ↓
Otsu 阈值、二值化、连通滤波、边界搜索、补线
    ↓
赛道中线与视觉偏差 err
    ↓
视觉纠偏 + 陀螺仪阻尼、前进速度规划
    ↓
vx 前进、vy 横移、omega 自转
    ↓
麦轮逆运动学 → FL / FR / RL / RR 四轮指令
    ↓
当前：限幅开环 PWM
编码器启用后：四轮速度 PID → PWM
```

| 任务 | 周期 | 主要工作 |
|---|---|---|
| 主循环视觉与决策 | 随摄像头出帧，约 50 Hz | 图像处理、运行状态推进、运动指令和遥测 |
| PIT_CH0 | 5 ms / 200 Hz | IMU 更新、电机输出；启用编码器后执行采样和轮速 PID |
| PIT_CH1 | 10 ms / 100 Hz | 按键扫描 |

车体坐标约定为 `vx > 0` 前进、`vy > 0` 左移、`omega > 0` 俯视逆时针左转；`gyro_z` 也统一为左转时为正。

视觉偏差定义为“赛道中线列坐标减去画面中心”。正常未镜像图像中，正偏差表示赛道位于画面右侧，应右转，因此默认 `CONTROL_IMAGE_TURN_SIGN=-1`。横移增益当前默认为 0，先使用前进和自转完成循迹。

KEY_1 发车，KEY_2 停车。连续出界达到 3 帧，或检测到第 2 次斑马线上升沿，也会触发停车；每次重新发车会重置本次运行的视觉停车计数。

当前 IMU 模块提供陀螺仪零偏校准、静止零偏跟踪和角速度滤波，没有接入 Mahony/EKF 姿态融合。另行下载的飞控参考仓库未包含在本工程中。

## printf 与 VOFA+ 调试

`debug_init()` 将 printf 重定向到库的调试串口，不额外初始化 UART6。

| 项目 | 设置 |
|---|---|
| 串口 | UART1 |
| 主板 TX | B12，接 USB 转 TTL 的 RX |
| 主板 RX | B13，接 USB 转 TTL 的 TX；仅接收遥测时可不接 |
| 地线 | 主板与串口模块共地 |
| 串口电平 | 3.3 V TTL |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| VOFA+ 协议 | FireWater |
| 数据格式 | 20 个逗号分隔数值，以 CRLF 结束 |

程序启动时会先输出初始化文字，进入正常遥测后输出数值行。四轮数据按 FL、FR、RL、RR 排列。

| 通道 | 内容 | 单位或说明 |
|---|---|---|
| 1–4 | 四轮实际速度 | cm/s；编码器禁用时为 0 占位 |
| 5–8 | 四轮目标速度 | cm/s，规划指令 |
| 9–12 | 四轮输出占空比 | % |
| 13 | 视觉偏差 err | 像素 |
| 14 | 自转指令 omega | deg/s |
| 15 | 实测 gyro_z | deg/s |
| 16 | 前进速度目标 | cm/s |
| 17 | 视觉处理耗时 | μs |
| 18 | 车辆状态 | 0 空闲、1 起步、2 运行、3 停车 |
| 19 | 停车原因 | 0 无、1 斑马线、2 出界、3 手动、4 堵转 |
| 20 | 横移速度目标 vy | cm/s |

## 后续接入编码器

安装编码器并确认四轮顺序、正转计数方向、编码器计数换算、减速比、轮径和底盘尺寸后，再将 `ENCODER_ENABLE` 改为 `1`，逐轮调试速度反馈和 PID。仅打开开关不会自动完成硬件标定和参数整定。

需要恢复无线调试时，将 `WIFI_SPI_ENABLE` 改为 `1`，配置连接参数；目标 IP 和端口由 `libraries/zf_device/zf_device_wifi_spi.h` 中的宏决定。
