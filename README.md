# PVC · RT1064 四电机麦轮循迹小车

当前版本日期：**2026-10-13**。配套上位机源码在[upper_computer](upper_computer/README.md)，可直接运行[单文件EXE](upper_computer/release/WiFiSPI_Monitor.exe)。

McarPVC 是基于 NXP i.MX RT1064 的四电机麦克纳姆轮循迹工程，使用总钻风 MT9V03X 摄像头获取赛道图像，通过麦轮运动学分配四个车轮的运动指令，并采集 ICM20602 姿态与角速度供实跑分析（已按实测安装符号启用初调陀螺阻尼）。

底层基于逐飞科技 RT1064 开源库，视觉算法移植自个人先前的 `summer-smartcar` 双电机加舵机项目。当前模块联调已通过，开始使用统一的正常运行框架。

## 当前版本

**当前入口：** main持续调用app_poll，正常视觉循迹与编码器闭环开启。固定前瞻60，取值50～70行；500ms起步包络，默认直道150、普通弯120、紧弯100cm/s，弯道稳定退出后恢复速度。视觉转向与少量横移经麦轮运动学分配四轮Target，5ms中断叠加陀螺阻尼并执行独立PI。上电等待K1，K2在10ms扫描中断消抖后直接清PWM，不依赖WiFi返回。在线巡航上限200只是允许范围，不是复位默认值。

**发送时机：** 连通即补发初始化日志；K1/K2只控制运动，IMU、图像、必要日志独立上传。参数内层148字节、生成周期50ms；图像最少66ms启动一帧，约15fps启动目标，实际完整帧率看上位机统计。主循环不再强制延时，由LPSPI1/eDMA TX30、RX31与异步状态机逐片推进。默认固定UDP 8081，通过MUDP类型头分参数/文字/图像，正常上传不切换socket；保留旧三端口兼容工程及接收确认、故障恢复。画面为原始灰度、最终边界/中线/补线及真实取值行标注。

**运行参数（全部在 `code/config/config.h`）：**

- 转向环：`CTL_OMEGA_KP1_DEFAULT=1.60`、`CTL_OMEGA_KP2_DEFAULT=0.012`、`CTL_OMEGA_KD_DEFAULT=0.30`、死区2px、限幅240°/s、陀螺阻尼 `CTL_GYRO_KD_DEFAULT=0.30`
- 横移辅助：`CTL_LATERAL_GAIN_DEFAULT=0.10` cm/s/px，上位机键 `lateral_gain`；偏差50px时横移5cm/s，与转向共用2px死区
- 四轮速度环：FL/FR/RL/RR Kp=0.22/0.20/0.18/0.20，Ki=0.0010、Kd=0、附加增益Kff=0；上位机不再提供速度环编辑，车端配置保持
- 速度：`CAR_TARGET_SPEED_CMS=150`、`CAR_START_RAMP_MS=500`；弯速默认120/100、进入需求70/140°/s、连续2帧确认；退出需求/偏差/实际转速≤45°/s、12px、40°/s持续200ms；减/加速250/100cm/s²
- 实时参数：车端GET/SET协议共36项，上位机保留23项可调参数（10项基础循迹/起步参数与13项弯道参数）；四轮速度环12项和ff不显示、不从调参页发送
- 符号：`IMU_MOUNT_YAW_SIGN=-1`（控制角速度左正右负，上传的原始 gz 仍左负右正）、`CONTROL_IMAGE_TURN_SIGN=-1`

调参顺序与"症状→参数"对照见下方 [转向与速度调参](#转向与速度调参) 一节。

**滚子安装方向：** 用户确认俯视且车头朝上，FL/RR为左上—右下，FR/RL为左下—右上，与当前逆运动学一致；四轮电机前进方向补偿不变。

用户提供L=20cm、W=18cm、周长19.5cm。编码器已回退逐飞原库一倍频（2026-10-07），按1024线、68/30齿传动计算119.02906 count/cm，速度cm/s、距离cm；原始累计值仍是整数计数。换算接口为 `encoder_set_counts_per_cm()` / `encoder_get_counts_per_cm()`，不再使用每米参数。2026-10-07手动转轮确认原FL/FR对应反了，已交换前轮硬件通道：FL=C2/C24，FR=C0/C1；方向补偿随通道交换为1/0/1/0。电机输出映射未改。

当前视觉处理和四轮轮速内环均已启用。

正常循迹入口统一调用应用层初始化和调度。IMU和编码器在5ms PIT采样，主循环处理视觉、按键事件和WiFi。默认接收端口8081（三种类型共用），下行命令到模块6666；旧三端口工程仍使用8081/8082/8083。原[正式运行框架说明](docs/正式运行框架说明.md)保留历史，当前协议以本README及[上位机说明](upper_computer/README.md)为准。

编码器采样与控制策略分开配置：四路计数一直更新。UDP参数包扩展为148字节，兼容原108字节前缀，追加视觉偏差、车体指令与处理/通信耗时。新版上位机选择“视觉循迹”预设。

## 硬件与接口

| 硬件 | 用途 |
|---|---|
| RT1064 主板 | 主控，程序初始化为 600 MHz |
| 总钻风 MT9V03X | CSI 并口摄像头，188 × 120 灰度图像 |
| 两块双路 DRV8701E | 四路有刷电机 DIR + PWM 控制，PWM 频率 17 kHz |
| ICM20602 | SPI4 六轴 IMU，当前控制主要使用 Z 轴角速度 |
| 四路正交编码器 | 一倍频采样、厘米换算；四轮速度闭环已启用（Kp/Ki/前馈在 config.h） |
| USB 转 TTL 串口模块 | 接收UART1备份事件日志，可选 |
| 四个按键 | 当前使用 KEY_1 发车、KEY_2 停车 |

四轮编号和接口如下，轮子顺序在控制、运动学和遥测中保持一致：

```text
           车头
    M1 左前     M2 右前
    M3 左后     M4 右后
```

| 车轮 | DIR | PWM |
|---|---|---|
| M1 / FL 左前 | C9 | C8 |
| M2 / FR 右前 | C7 | C6 |
| M3 / RL 左后 | D2 | D3 |
| M4 / RR 右后 | C10 | C11 |

ICM20602 使用 SCK=C23、MOSI=C22、MISO=C21、CS=C20；该接口由库中的 `zf_device_icm20602.h` 定义。电机和编码器的方向、底盘尺寸及控制参数在 `code/config/config.h` 中配置。

## 编译与下载

1. 使用 Keil MDK 5 打开 `project/mdk/rt1064_single_udp.uvprojx`（输出Objects_SingleUDP），上位机选择“单端口MUDP”；若用兼容三端口则打开 `rt1064_curve_legacy.uvprojx`（输出Objects_CurveLegacy），选择“旧版三端口”。原 `rt1064.uvprojx` 也按当前源码默认编译单端口。
2. 选择工程目标 `nor_sdram_zf_dtcm`，使用 ARM Compiler 6。本机已使用 ARMCLANG V6.24 完成编译；工程引用的设备包为 `NXP.MIMXRT1064_DFP.15.0.0`。
3. 确认设备为 `MIMXRT1064DVL6A`，执行 Build；工程已包含 SDK、逐飞库、业务源码和分散加载文件。
4. 在 Debug / Utilities 中选择与 RT1064 匹配的 ARM CMSIS-DAP 或 J-Link，确认调试连接和 Flash 下载配置后烧录。

`libraries` 中的 `.a`、`.lib` 文件属于工程依赖，需要保留。`Objects`、`Listings` 等编译结果不纳入版本管理，编译时会重新生成。

## 控制流程

```text
摄像头灰度图像
    ↓
Otsu 阈值、二值化、连通滤波、边界搜索、补线
    ↓
赛道中线与视觉偏差 err
    ↓
转向环 ω = −(KP1·e + KP2·e|e| + KD·Δe)     ← 视觉外环，约 50 Hz，随出帧更新
    ↓
5 ms 合成：vx 起步/弯道速度规划 + vy 横移 → ω 叠加陀螺阻尼并限幅 → 麦轮逆运动学
    ↓
FL / FR / RL / RR 四轮目标速度
    ↓
四轮独立速度 PI（附加项默认关闭） → PWM（17 kHz，DIR + PWM）
```

| 任务 | 周期 | 主要工作 |
|---|---|---|
| 主循环视觉与决策 | 随摄像头出帧，约 50 Hz | 图像处理、运行状态推进、运动指令和遥测 |
| PIT_CH0 | 5 ms / 200 Hz | IMU 更新、电机输出；四路计数持续采样，闭环启用后执行轮速 PID |
| PIT_CH1 | 10 ms / 100 Hz | 按键扫描 |

三个时间尺度分工：**视觉外环（~50 Hz）决定往哪转**；**5 ms 合成决定转多少（斜坡/限幅/陀螺阻尼）**；**5 ms 轮速环决定四个轮子各自多快**。调参时结合 `vis_err_px`、`omega_cmd_dps`、四轮目标/实际速度判断偏差出在哪一层。在线参数默认只在RAM生效，断电恢复config.h；本地方案可以保存并重新应用。

车体坐标约定为 `vx > 0` 前进、`vy > 0` 左移、`omega > 0` 俯视逆时针左转；`gyro_z` 也统一为左转时为正。

视觉偏差定义为“赛道中线列坐标减去画面中心”。正常未镜像图像中，正偏差表示赛道位于画面右侧，应右转，因此默认 `CONTROL_IMAGE_TURN_SIGN=-1`。本轮横移增益为0.10cm/s/px，`vy=-err×lateral_gain`，共用2px死区。正偏差同时向右转、向右横移，运动学合成四轮目标后由各轮PID执行；横移修位置，不独立锁定车头航向。

KEY_1 发车，KEY_2 停车。连续出界达到 3 帧，或检测到第 2 次斑马线上升沿，也会触发停车；每次重新发车会重置本次运行的视觉停车计数。

当前IMU统一采集六轴数据并进行四元数姿态解算；固定三轴校准用于姿态和上位机，控制Z轴保留静止零偏跟踪与低通滤波。yaw是上电相对角，不是绝对航向。

## 上位机通信

默认单端口8081，外层8字节MUDP头按类型区分参数/日志/图像；参数内层为148字节小端，摄像头内层为MCAM v1格式3。旧三端口模式可选。上位机默认视觉循迹37字段，支持原始灰度叠线、实时曲线、三维模型、日志和23项实时调参。WiFi目标、端口和节拍在config配置；UART1 B12/B13、115200仅作启动/事件日志备份。

实跑数据用 `tools/analyze_capture.py`（本地工具，按 .gitignore 不入库）判读：`python tools/analyze_capture.py` 会自动切出"电机有输出"的实跑段，打印 `|err|` 趋势、ω 顶限幅比例、转向达成率（真实 yaw 速率 / 指令）、四轮跟踪误差、占空比峰值，以及视觉单帧耗时与 WiFi 服务耗时。

## 转向与速度调参

上位机06实时调参页先读取车辆参数，再单项应用，匹配编号/实际值回执后才确认。命令发到模块6666，ACK走当前模式日志通道。保留23项循迹/起步/弯道参数，速度环不再提供编辑；原23/36项方案可导入并忽略速度环字段，新方案只保存当前23项。修改不发车，不清正在运行的PI累计输出；起步时间与弯道开关仅停车改。cruise_cms=0仍可能转向，停车按K2。

| 数据现象 | 调整入口 | 原因与代价 |
|---|---|---|
| 偏差明显，但omega较小且未触顶 | omega_kp1；大偏差时omega_kp2 | 增大偏差到转向的映射；过大容易摆动 |
| omega频繁触顶、轮速能跟踪 | omega_max_dps | 放宽允许转向；滑移和电机能力仍会限制实际转向 |
| 正确轮速目标已经不同，但某轮持续跟不上 | 保存轮速数据后分析车端速度环 | 上位机已移除该组编辑；需要时再修改config并单独验证 |
| 普通偏差能转，直道左右摆 | 降omega_kp1，适量gyro_kd | 视觉力度与陀螺阻尼需配合；gyro过大会转向变钝 |
| 入弯反应晚 | preview_row向较小行；omega_kd小步试调 | 更早看远处，或响应偏差变化；可能放大远端错误及噪声 |

先核对边界和补线，再一次改一个参数、保存同赛道数据比较。当前逐函数说明见[控制链条说明](docs/当前版本控制链条逐函数讲解_20261013.md)及其版本提示；最新问题、修改和建议见[前瞻60分析](docs/前瞻60_单边中线与出弯斜行分析_20261013.md)。下面参数迭代记录属于当时版本，不覆盖顶部当前配置。

## 参数迭代记录

### 2026-10-09 第一轮：改善出弯后的轮速响应

**目标：** 根据“小车转弯后的直道不直，影响后续弯道”的观察，先迭代现有速度PI；本轮不修改IMU纠偏系数或机制，也不提高视觉增益。

**数据来源：** `数据_20261009_202707_536870.csv`，位于电脑的 `AppData/Local/McarWiFiMonitor/captures`，以及同次20:24:33调试日志。342个参数包中82个有电机输出，车端采样计数对应运行跨度4.30秒；最终日志为 `STOP reason=2`（丢线停车）。使用 `samples×0.005s` 计时，不以电脑收包间隔计算响应。主要比较窗口为首个输出包后1.00～3.65秒，暂排除起步及接近丢线尾段；没有同步赛道视频，不能仅凭CSV确认具体直道位置或人工干预时刻。

**判断依据：**
